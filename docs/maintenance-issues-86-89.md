## 잠금과 복구

`maintenance.guard/` 는 새 버전의 기록자와 회수자가 함께 쓰는 상호 배제 디렉터리다. 먼저 유일한 임시 디렉터리에 owner 파일을 다 쓰고, 비어 있지 않은 디렉터리를 원자적으로 공개한다. 회수는 종료가 확인된 owner 의 유일한 파일만 삭제한 뒤 비재귀 rmdir 을 쓴다. 다른 프로세스가 이미 새 잠금을 얻었더라도 그 새 owner 파일을 삭제하거나 그 디렉터리를 옮기지 않는다.

옛 버전 유지보수기를 막기 위해 `maintenance.lock` 도 유지하며, 맨 PID, pid:nonce, host:pid:nonce 옛 기록과 호환한다. 새 기록은 hostname, PID, 생성 시간, 고유 token 을 담는다. 같은 기계에서 PID 가 사라졌거나, 시스템 프로세스 시작 시간이 잠금 생성 시간보다 명확히 늦을 때만 회수한다. **"30분 초과"나 "하트비트 미갱신"으로 잠금을 삭제하지 않는다**; 옛 버전 장기 작업에는 애초에 하트비트가 없었다. 읽기 실패, 다른 기계의 기록, 무효 PID/내용, 프로세스 정보 확보 실패는 모두 현장을 보존하고 보고한다. PID 재사용 판정에는 실제 프로세스 시작 시간이 필요하고 프로세스 이름만 봐서는 안 된다.

CLI 와 패널의 수동 정리 진입점도 같은 유지보수 잠금을 얻어, 만들어지고 있는 백업 객체를 정리하지 않는다.

설치/롤백은 각 비동기 단계가 끝난 뒤, 매니페스트와 설정을 쓰기 전, 정리와 실패 복구 전에 소유권을 확인한다. 잠금을 잃거나 잠금 읽기가 실패하면 이후 커밋을 중단하고, 옛 checkpoint 를 새 기록자의 파일 위로 자동 복구하지 않으며 복구 디렉터리를 보존한다. 이미 기동된 외부 설치기는 JavaScript 검사 한 번으로 되돌릴 수 없으므로 정상적인 활성 프로세스가 자동으로 잠금을 빼앗기게 해서는 안 된다.

사용자가 직접 잠금을 삭제하는 것은 권장하지 않는다. 소유가 불명확하면 해당 프로세스, 잠금 시간, 조작 기록, profile 공유 여부를 먼저 확인하고, 민감정보를 제거한 증거만 수집하며 프롬프트, 전체 profile, 자격 증명을 요구하지 않는다.

## Windows #89

4090 에서 임시 Electron 런타임, 임시 holder 프로세스, 가짜 아카이브를 쓰고 정식 DSH 는 기동·정지·수정하지 않았다:

1. 일반 Electron 런처 종료: 기존 도우미는 계속 실행되고, holder 가 종료된 뒤 테스트 아카이브 이동이 성공했으며 백업 내용이 일치했다.
2. `scripts/check-windows-job-handoff.ps1`: 격리 Electron 을 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 를 명확히 설정한 Job Object 안에 넣고, 도우미도 그 Job 에 속함을 확인했다. 테스트 Job 을 닫자 도우미가 종료되었고 상태는 waiting_for_quit 로 남았으며 테스트 아카이브는 원래대로였다. 보고서의 고장 증상을 재현했다.

이것은 특정 프로세스 생애주기 메커니즘이 그 증상을 만들 수 있음을 증명하며, **보고자의 DSH 가 반드시 같은 Job 으로 관리된다는 증명은 아니다**. 기동 방식(일반 데스크톱/관리자/작업 프록시), 완전 종료 방식, 종료 전 helper 의 부모 프로세스와 Job 소속을 여전히 확인해야 한다. 부모-자식 관계만으로 Windows 가 모든 자손을 자동 종료한다고 단정할 수 없다.

이 스크립트는 TEMP 아래의 격리 Electron 만 받고, 종료하는 것은 자신이 만든 테스트 프로세스뿐이다. 정식 DSH 에 실행할 수 없고 패키지 교체 자동 수정에도 쓰지 않는다. 재현 조건이 충족되지 않으면 실패하고 증거를 보존한다.

## 인수

잠금 테스트는 실제 자식 프로세스 크래시, 실제 다중 프로세스 상호 배제, 그리고 통제된 교차, PID 재사용, 옛 형식, 다른 기계/미지 잠금, 디스크 쓰기 실패, 잠금 읽기 실패를 포함한다. 설치/롤백 잠금 상실 테스트는 격리 profile 과 구성된 설치기 실패를 쓴다. 전체 CLI/pnpm 설치, 마이그레이션, 롤백은 `scripts/check-install-lifecycle-runtime.mjs` 가 격리 사본에서 따로 수행한다. 둘을 전체 데스크톱 UI 인수라고 섞어 부르지 않고, 모델 응답 효과도 테스트하지 않는다.
