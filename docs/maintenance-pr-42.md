# PR #42: Linux 설치와 제거 경계

이 변경은 Linux CLI/Web 설치 진입점을 추가하며, 패치 표, 프롬프트, 권한 선택, 사용자 설정을 바꾸지 않고 패치를 자동 적용하거나 호스트를 재시작하지도 않는다.

## 검토에서 나온 발견과 수정

- **제거가 심볼릭 링크를 따라감**: 정리 목록이 링크에 다시 realpath 를 수행해 외부 디렉터리 보호를 우회했다. 이제 링크의 원래 경로 그대로 링크를 삭제하며(끊긴 링크와 Windows junction 포함) 외부 소스, 공유 의존성, 외부 profile 을 지우지 않는다. 일반 플러그인 디렉터리는 현재 DSH home 안에서만 정리한다. 되돌리기나 등록 해제가 실패하면 정리를 수행하지 않는다.
- **설치 실패 시 진입점을 미리 전환**: 사용자 호스트 사본 생성과 진입점 활성화를 분리한다. 먼저 패키지를 검증하고 사본을 준비한 뒤 마이그레이션을 실행한다. 마이그레이션이 성공해야 `~/.local/bin/dsh` 를 원자적으로 전환한다. 실패하면 원래 진입점을 그대로 두고 최초 설치 실패 시에는 새 진입점이 남지 않는다. 활성화하지 않은 완전한 사본은 재시도에 쓰도록 남기며, 다른 프로세스가 쓸 수 있는 사본을 자동으로 삭제하지 않는다.
- **동시 수정**: 마이그레이션 중 사용자가 진입점을 교체하면 활성화를 멈추고 명확히 오류를 낸다. 사용자 명령을 덮어쓰지 않는다. 이때 플러그인 마이그레이션은 이미 성공했을 수 있지만 기동 진입점은 전환되지 않은 상태이므로, 현재 진입점을 확인한 뒤 재시도하며 오류를 전부 롤백된 성공으로 해석하지 않는다.
- **경로 별칭**: 테스트와 사용자 사본 위치 판정 모두 실제 경로로 처리하며, macOS 의 `/var` 별칭과 Linux 의 심볼릭 링크 home 을 지원한다.

## 검증 범위

`npm test` 는 실제 파일시스템 링크/제거 테스트와, 압축을 푼 뒤 마이그레이션 하위 프로세스의 성공/실패 테스트를 포함한다. 기존 진입점 불변, 최초 설치 시 비활성화, 설정 바이트 불변, 동시 진입점 충돌, 복사 실패 정리, 무관 파일 보존, 기존 진단과 기능 회귀까지 검증한다. Linux 읽기 전용 디렉터리 테스트는 root 가 아닌 Linux 사용자로 실행해야 한다. Windows 는 junction 으로 제거 경계를 검증하며 플랫폼 건너뜀을 통과로 세지 않는다.

GitHub 3 플랫폼 installer 매트릭스는 전체 테스트와 패키징 smoke 를 실행한다. Windows 는 두 종류의 PowerShell 테스트와 실제 Electron 인계 테스트를, macOS 는 실제 Electron 진단 테스트를 추가로 수행한다. Linux shell 진입점과 다운로드 래퍼 테스트는 격리 대역을 쓰며 실제 모델에 로그인해 작업을 끝내는 것과 같지 않다. `linux-runtime` 작업은 공식 `@deepseek-ai/dsh@0.2.1-rc.2` 를 따로 설치하고 격리 사본을 읽기 전용으로 둔 뒤 bootstrap, 사용자 사본 CLI, 플러그인 임포트, 백업/롤백, 실패 복구를 실제로 실행한다. 모델 서비스를 기동하지 않으며 완전한 그래픽 인터페이스나 모델 능력 검수와 같지 않다.

유지보수 시 사용자의 전역 npm 소스, 프록시, 권한, 프롬프트, 실행 중인 서비스를 바꾸지 않는다. 사본 준비에는 sudo 가 필요 없고 시스템 디렉터리는 항상 원래대로 둔다.
