# 플러그인 마켓에서 Purge 설치 또는 마이그레이션

최초 설치 시 dsh-market 에서 `wnduddld0513/dsh-purge-kr` 를 검색할 수 있다. 저장소 작성자와 패키지명 `dsh-purge-community` 를 확인한다. 같은 이름의 미러는 같은 배포 출처가 아니다. `dsh plugin add dsh-purge` 나 맨 패키지명 `dsh-purge-community` 를 실행하지 않는다: 이 프로젝트는 GitHub Releases 로 배포하며 그 두 npm 이름에 의존하지 않는다.

## 옛 버전이 설치된 경우: 먼저 제거하지 않고 바로 마이그레이션

마켓이 "이미 dsh-purge 로 설치됨"이라고 알려도 커뮤니티 버전이 설치되었다는 뜻이 아니다. 두 패키지는 같은 진입점 ID 를 쓰므로 동시에 강제로 활성화하면 충돌한다. [README 의 macOS / Windows 설치 진입점](../README.md)을 사용한다. 그것이 출처와 SHA256 을 검증하고, 먼저 백업한 뒤 현재 profile 로 마이그레이션한다. **먼저 제거하거나 DSH_HOME 을 삭제하거나 프롬프트를 비우지 않는다.**

1. 대상 DSH, 데이터 디렉터리, profile 을 확인한다. 설치기의 `--dry-run`(Windows `-DryRun`)을 실행해 대조하고, 경로가 유일하지 않으면 명시적으로 지정한다. 다른 사용자의 디렉터리를 그대로 베끼지 않는다.
2. dry-run 을 빼고 마이그레이션을 실행한다. 다른 설치 작업은 미리 끝내야 한다. 채팅을 중단하거나 DSH 를 자동 재시작할 필요는 없다.
3. 설치기는 프롬프트, 규칙, 업데이트 선호, 권한, 다른 플러그인, 옛 패키지 파일을 보존한다. Purge bundle 과 식별된 옛 패키지 `name` 참조만 교체하고 설정 값과 주석은 유지한다.
4. 성공하면 `backup_id` 를 기록한다. 사용자가 편할 때 직접 종료 후 재실행하고 로드된 버전을 확인한다. 설치, 호스트 패치 적용, 재시작은 세 개의 독립 동작이며 뒤의 두 가지는 자동 실행하지 않는다.

### Agent 가 반드시 주의할 것

- 공식 호스트 CLI 의 설치 규칙은 같지만, 서드파티 마켓은 디렉터리 필터링, 중복 설치 방지, 출처 변환, 로드 검증을 추가할 수 있다. 마켓 웹 페이지에 플러그인이 나열되었다는 것이 그 `index.json` 에 그 플러그인이 포함되었다는 뜻은 아니다.
- npm 배포가 없다는 것이 설치 패키지가 없다는 뜻은 아니다. 독립 인덱스는 <https://wnduddld0513.github.io/dsh-purge-kr/index.json> 이며, Git 버전은 전체 커밋 SHA 로 고정한다. 서드파티 인덱스 누락은 생성기를 고쳐야 하고, npm 메타데이터를 위조하거나 무결성 검증을 낮춰서는 안 된다.
- 마이그레이션은 `dsh-purge`, redteam, presets, store, ui 의 표준 진입점만 식별한다. 수동 `insert`, 미지 ID, 동적 패키지명, 잘못된 YAML 은 실패로 유지하고 의존성을 복구한다. 구체적 진입점 충돌을 보고해야 하며, 오류를 없애려고 인자를 삭제하거나 무작정 비활성화할 수 없다.
- `migrated_references` 는 실제로 재작성한 패키지 참조 수다. 0 이 실패는 아니다: 명시적 옛 패키지 덮어쓰기가 없으면 설정을 바꿀 필요가 없다. 성공 후에는 활성화 목록에 커뮤니티 패키지만 있는지, 설정 합성에 중복 ID 가 없는지, 사용자 설정 값이 남아 있는지 확인한다.
- 롤백은 `purge-community rollback <backup_id>` 를 쓰고, 옛 패키지 진입점을 복원하면서 현재 설정 값을 보존한다. 설정이 동시에 수정되었거나, 마이그레이션 기록이 손상되었거나, 복구가 실패하면 명확히 보고하고 복구 디렉터리를 보존한다. 백업이 있다는 것을 롤백 성공으로 볼 수 없다.
- 실패 시에는 마스킹한 마켓 이름/버전, DSH 버전, 시스템, 설치 출처, 오류 코드만 요구한다. 프롬프트 전체, 키, 설정, 백업을 수집하지 않는다.

## 테스트와 경계

`scripts/check-market-migration-runtime.mjs <공식CLI> <옛버전tgz> <후보tgz>` 는 완전히 새로운 격리 home 을 만들어 실제 설치, 설정 합성, 롤백, 재업그레이드, 실패 복구를 수행하고 비공개 내용 센티널을 검사한다. 호스트를 기동하거나 플러그인 apply 를 실행하지 않으며 전체 모델 동작 테스트를 뜻하지 않는다. Mac 과 Windows 모두에서 실행해야 한다.

서드파티 dsh-market 의 마이그레이션 안내와 커뮤니티 인덱스 생성기는 그 유지보수자가 병합·배포해야 한다. 우리의 새 독립 설치기는 먼저 마이그레이션에 쓸 수 있지만, Purge 를 업데이트한다고 아직 Purge 를 로드하지 않은 마켓 차단 로직이 바뀐다고 주장할 수 없다.
