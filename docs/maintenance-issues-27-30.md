# 업데이트 무결성과 진단 검토(#27–#30)

이번 변경은 업데이트, 백업 롤백, 버전 비교, 진단만 다룬다. 프롬프트 필터 정책, 권한 설정, 도구 표, 사용자 설정은 바꾸지 않았고, 호스트 패치 자동 적용, DSH 종료나 재시작도 하지 않는다.

## #28: profile 별 점검과 재시도

옛 로직은 어떤 설치든 성공하면 설치된 것으로 보았고, 현재 플러그인 사본의 버전으로 업데이트를 확인했다. 두 profile 이 부분 성공하면 실패한 사본이 누락될 수 있었다.

새 로직은 각 profile 의 `node_modules/dsh-purge-community/package.json` 을 하나씩 읽는다. 같은 패키지 디렉터리를 공유하는 profile 도 따로 처리하는데, 매니페스트와 링크가 각각 독립이기 때문이다. 패키지가 없거나 읽을 수 없으면 수리가 필요한 상태로 표시하고 최신으로 보지 않는다.

- `ok` 는 모든 대상이 성공했다는 뜻이고, `applied` 는 이번에 실제로 최소 하나의 대상을 바꿨다는 뜻일 뿐이다.
- 일부가 실패하면 `hasUpdate` 와 대상별 오류를 유지하고, 전역 버전 pin 을 커밋하지 않으며, 자동 업데이트 완료 보호 표식을 쓰지 않는다.
- 다음 자동 점검도 사용자의 점검·설치 스위치와 버전 고정을 따른다. 디스크에 버전 분열이 확인된 경우에만 "재시작 대기" 보호를 넘어 실패한 대상을 보충 설치한다.
- 목표 버전에 이미 도달한 profile 은 다시 설치하지 않는다. 자동 업데이트는 더 새로운 사본을 다운그레이드하지 않는다. 사용자가 과거 버전을 명시적으로 고르면 여전히 되돌릴 수 있다.
- 설치 전에 백업하고, 실패하면 대상별로 롤백하며, 설치 후 실제 패키지 버전을 대조한다. 릴리스 버전을 실행 중 버전으로 둔갑시키지 않는다.
- 과거 고정 버전으로 수동 전환하다 일부가 실패하면 실패를 계속 표시하고 그 명시 버전으로 재시도해야 한다. 원래 pin 을 임의로 바꾸거나 자동 업데이트로 전환하지 않는다.

## #29: 옛 ZIP 채널의 검증

정식 TGZ 채널에는 원래부터 SHA256SUMS 검증이 있었다. 이번에 보강한 것은 업스트림 소스 ZIP 경로다:

1. GitHub API 로 사용자가 고른 브랜치/태그를 완전한 commit SHA 로 해석한다.
2. 그 commit 의 전체 Git tree 를 읽는다. 잘림, 알 수 없는 파일 형식, 잘못된 경로는 즉시 실패한다.
3. 고정 SHA 의 codeload ZIP 만 내려받고, 다운로드 도중 이동하는 브랜치를 따라가지 않는다.
4. 크기 제한이 있는 Node 해제기를 쓰고, 일반 파일/디렉터리만 만들며, 아카이브 안의 심볼릭 링크는 만들지 않는다.
5. 모든 파일을 Git blob 형식으로 객체 다이제스트를 계산해 그 commit 의 tree 와 비교한다. 파일이 많거나 적거나 내용이 바뀌면 모두 실패한다. 전부 통과한 뒤에만 설치 디렉터리에 쓴다.
6. 실제 검증한 commit 을 기록하고, 설치 후 이미 이동했을 수 있는 브랜치를 다시 조회하지 않는다.

이것은 "내려받은 내용이 GitHub API 가 가리킨 commit 과 일치한다"는 증명이며, 배포자 서명이나 업스트림 코드 안전성 인증은 아니다. 신뢰 원천은 여전히 GitHub HTTPS/API 다. API 를 쓸 수 없거나, 레이트 리밋이 걸리거나, 매니페스트가 불완전하면 실패 상태를 유지하고 검증 없는 설치로 낮추지 않는다. 사용자 설정, 원래 설치, 백업은 보존한다.

## PR #27 검토와 보강

기여자의 진단, 버전 비교, 상태 스탬프, 짧은 점유 재시도, 롤백 수정을 유지하고 다음을 보강했다:

- 상태 읽기가 예외를 던지거나 불완전한 레코드를 반환하면 unknown 이며, 전부 초록으로 표시할 수 없다. 명시적 `missing_file`/`na` 는 여전히 "상태가 반환되지 않음"과 구분한다.
- SemVer 는 build metadata 를 무시하고, 사전 릴리스 숫자 필드는 정수로 비교하며, Number 정밀 범위를 넘는 숫자도 지원한다.
- 롤백할 때 백업에 포함되지 않은 `node_modules` 와 `.git` 은 보존한다. 어느 하나라도 되돌리는 데 실패하면 이번 롤백을 취소하고 오류를 낸다. retired 디렉터리만 남기고 성공을 선언할 수 없다.
- 일반 파일 스냅샷 복사는 rwx 권한을 보존해, 롤백 후 CLI 실행 비트를 잃지 않게 한다.
- 새 설치가 실패해 생긴 반쯤 설치된 디렉터리는 격리 위치로 옮겨 진단 증거로 보존한다. 원래 있던 디렉터리는 임의로 삭제하지 않는다. 설치기 오류에도 스냅샷 ID 는 유지한다.

경계: 패키지 관리자 실패 후 전체 의존성 그래프/잠금 파일을 자동 복구하는 것은 이번에 추가된 트랜잭션 보장이 아니다. 기존 스냅샷 롤백 능력은 유지한다. 매니페스트만 복구하는 실패 경로를 전체 의존성 그래프 롤백이라고 부르지 않는다.

## #30: 일반 작업 능력 조사

현재 "모델 지능 저하"를 확인할 수 없고, "반드시 사고를 중단시킨다"거나 "작업을 쪼개야만 하거나 플러그인을 꺼야 한다"는 결론을 뒷받침하는 증거도 없다.

격리된 일반 작업 관찰(모델 호출 없음, 사용자 설치 조작 없음):

| 항목 | 관찰 |
| --- | --- |
| 프로젝트 규칙과 메모리를 system section 으로 수용 | 해당 필터 정책을 켜면 제거되고, 해당 필터를 끄면 유지된다 |
| 도구 설명, 스킬 카탈로그, 일반 사용자 작업 픽스처 | 두 그룹 모두 유지 |
| 질문 기본 대기, 명시적 60초 | 현재 코드는 각각 120초, 60초를 유지한다. 더 이상 1초로 고정하지 않는다 |
| 명시적 무한 대기 | 여전히 네이티브와 다르다: 현재 300초로 줄인다 |
| 끼어들기 | 실제 메서드 본문 회귀 테스트가 있다. 그것으로 보고자의 설치가 새 코드를 적용·로드했다고 증명할 수는 없다 |

**수용 위치가 중요하다**: 위 규칙 손실은 특정 system section 의 동작만 증명하며, 모든 워크스페이스 규칙이 사라졌다는 뜻은 아니다. DSH rc.2 의 메시지형 `agent-instructions` 와 system section 은 다른 경로다. 사용자 버전, 정책, 실제 입력, 호스트 로드 상태를 각각 대조해야 한다.

후속 모델 수준 대조는 DSH/모델 버전, 추론 등급, 도구, 일반 작업 저장소를 고정해야 한다. 깨끗한 네이티브 사본과 플러그인 사본을 쓰고, 최소 세 번 교차 반복하며, 완료율, 제약 준수, 반복 도구 호출, 소요 시간, token 을 기록한다. 플러그인만 끄는 것은 깨끗한 기준선이 아니다. 호스트 디스크 수정이 여전히 남아 있을 수 있다.

보고자에게 요청할 것: DSH 와 플러그인 버전, 공개 가능한 일반 작업 하나, 기대 결과와 실제 오류, 업데이트 후 수동으로 적용하고 다시 열었는지 여부. 개인 프롬프트, 전체 설정, 토큰, 전체 채팅 기록을 요구하지 않는다. 재현 가능한 샘플을 얻기 전까지는 조사 상태를 유지하고, 이번 유지보수가 모델 출력 품질을 개선한다고 약속하지 않는다.
