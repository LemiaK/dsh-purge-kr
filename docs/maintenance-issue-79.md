# #79 / #77: 런타임 링크 마이그레이션과 오류 상세

## 재현된 고장

옛 버전이 평면 디렉터리에 `app/runtime → ../runtime` 를 만들었고, 이후 호스트 레이아웃이 `runtime/<process.arch>/primary-runtime/...` 로 바뀌면, 옛 링크는 살아 있지만 CLI 의 평면 로드 경로를 만족하지 못한다. 1.6.51 은 이 경우 `runtime_conflict` 를 반환하고, 더 이전의 평면 탐지는 `missing_runtime` 을 반환했다. 이것은 재구성해 검증한 고장 경로이며, 보고자의 시스템과 디렉터리 레이아웃이 확인되었다는 뜻은 아니다.

백엔드의 적용 실패 응답에는 `cli_repair` 가 있었지만 옛 프런트엔드는 총 오류 문자열만 남겼다. 구체적 reason, 런처 읽기/쓰기 오류, 복구 상태는 버려졌다. 1.6.54 는 이 화이트리스트 필드를 표시하고 HTTP 오류와 원래 실패 상태를 유지하며, 전체 설정/프롬프트를 펼치지 않는다. HTTP 200 이지만 적용이 완전히 성공하지 못한 응답도 같은 상세 오류 형식을 쓴다.

## 마이그레이션과 복구 경계

- 같은 설치의 바깥 runtime 에 대한 옛 링크만 마이그레이션한다. 현재 프로세스의 아키텍처 디렉터리와 pnpm 로더가 실제로 존재하고 그 runtime 안에서 해석되어야 한다.
- 옛 링크를 먼저 고유한 `.dshpurge-link-*.bak` 로 이름을 바꾸고 새 링크를 만든다. Windows 는 절대 Junction, macOS 는 상대 심볼릭 링크를 쓴다.
- 생성/검증이 실패하면 존재할 수 있는 새 링크를 따로 남겨 두고 옛 링크를 복원한다. 복원이 실패하면 `rollback_failed` 와 백업 위치를 명시적으로 반환한다. 링크나 대상 파일을 재귀적으로 삭제하지 않는다.
- 실제 디렉터리, 다른 대상을 가리키는 활성 링크, 외부 아키텍처/로더, 미지 아키텍처, 권한 및 읽기 실패는 덮어쓰기나 건너뛰기로 해결하지 않는다. 확인 중에 대상이 사라진 경우도 옛 링크 손상으로 오판하지 않는다.
- 백업 성공이 마이그레이션 성공은 아니고, 마이그레이션 성공이 호스트 재로드는 아니다. 플러그인은 DSH 를 자동으로 종료하거나 다시 열지 않는다.

## 재현과 인수

유지보수 스크립트 `scripts/check-runtime-migration.mjs` 는 `.purge-install-test-fixture` 표식이 있는 새 임시 CLI 사본만 쓸 수 있다. Mac 사본에는 `.app` 이나 Info.plist 신원이 있어서는 안 된다. 인자는 테스트 사본 경로와 검증된 릴리스 패키지의 압축 해제 디렉터리다. 반드시 사본 자체의 Electron 을 `ELECTRON_RUN_AS_NODE=1` 로 실행해야 한다.

스크립트는 먼저 옛 릴리스 패키지의 실제 링크 함수로 평면 링크를 만들고 pnpm 을 실행한 뒤, 아키텍처 레이아웃을 재구성한다. 옛 버전 실패를 검증한 뒤 링크 생성과 복구 실패를 주입하고, 원래 링크/백업/대상 내용을 확인한 다음 새 마이그레이션과 실제 pnpm 을 수행한다. 오류 주입은 실패 분기에만 쓰고, 파일 시스템과 Electron/pnpm 은 실제로 실행한다.

그다음 `scripts/check-install-lifecycle-runtime.mjs` 를 실행한다: 실제 공식 CLI/pnpm 으로 새 설치, 옛 패키지 마이그레이션, 커뮤니티 패키지 및 별칭 업그레이드, 롤백, 재업그레이드. 실제 패키지 관리자 트랜잭션 뒤에 검증 실패를 주입해 의존성 목록, 잠금 파일, 설정, 사용자가 이후 편집한 내용의 복구/보존을 확인한다. 설치 과정은 호스트 서비스를 기동하지 않고 호스트 패치를 적용하지 않으며 모델이나 프리셋 드롭다운을 테스트하지 않는다.

이것은 전체 데스크톱 UI 인수와 다르다: 디렉터리 변화는 수동으로 재구성했고 호스트 자동 업데이터는 실행하지 않았다. 보고자의 특정 클라이언트, 마켓 클릭, 프리셋 재시작 후 사라짐은 검증하지 않았다. HTTP 오류 회귀는 실제 로컬 HTTP 서비스와 실제 프런트엔드 파서를 쓰고, 응답은 구성된 진단 데이터이며 정식 DSH 에 적용 인터페이스를 호출하지 않는다.

## 보고자에게 수집할 것

제거 후 재설치가 필요 없다. 실행 중인 플러그인 버전과 DSH 릴리스 이름/버전, 운영체제와 아키텍처를 먼저 대조한다. 업그레이드 후에도 실패하면 이번 상세 오류의 reason/code/복구 결과를 제공하면 되고 경로는 마스킹해도 된다. 프롬프트, 전체 설정, 키, 환경 변수를 요구하지 않는다. 프리셋이 재시작 후 사라지는 것은 별도 확인 대기 상태로 두고, 총 오류만으로 사용자가 "적용"을 누르지 않았다고 귀인하지 않는다.
