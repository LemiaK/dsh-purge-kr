# 끼어들기 전달과 업그레이드 인수(1.6.27)

## 이번에 고친 것

DSH 의 `next-step` 은 현재 라운드의 다음 단계에서 소비된다는 뜻이고, `next-turn` 은 이후 라운드를 뜻한다. 끼어들기는 이미 나간 모델 요청을 중단하지 않고 다음 단계 경계에서 소비된다.

업스트림 1.1.69 는 공개 `steer()` 를 바꿨고, 1.1.71 은 하위 계층만 복구하면서 UI 대기열 끼어들기는 여전히 followup 으로 바꿨다(업스트림 #121). 이 포크 1.6.26 은 UI 분기를 복구했지만 새로 추가한 강등 로직이 두 상태를 뒤섞었다: 메시지가 이미 next-step 이거나, agent 가 더 이상 running 이 아닌 경우. 둘 다 삭제하고 next-turn 에 다시 덧붙였다.

결과적으로: 첫 끼어들기가 성공한 뒤 반복 요청이 그 전달을 철회했고, 유휴 대기열 [a,b] 에서 a 에 끼어들면 [b,a] 가 되었다. 프런트엔드는 만료 요청을 무동작으로 수렴시키는 데 의존하고, 아직 갱신되지 않은 대기열 프로젝션을 쓸 수 있으므로, 이런 경우를 일괄 followup 으로 변환할 수 없다.

1.6.27 은 네이티브 가드, prompt(mode) 분기, 대기열 case, 공개 steer 만 복구한다. 중복/만료 요청은 네이티브 오류 코드와 프런트엔드 처리를 유지하고, 메시지를 재생성하거나 재정렬하지 않는다. 네이티브 중단 라운드 뒤의 전송 처리도 유지한다. 답변 대기, 다른 패치, 사용자 프롬프트는 이번 변경 범위가 아니다.

## 정밀 마이그레이션과 상태

#90 은 controller 와 agent-loop 를 커버한다:

- 네이티브 파일: 필요한 분기가 완전함을 확인하면 완료로 보고 쓰지 않는다.
- 옛 #85, 대기열 #86, 1.1.69 공개 steer, 1.1.71 복구 주석, 1.6.26 #90: 이미 식별된 조각만 역방향 교체한다.
- 옛 버전 혼합 잔여물: 대상 파일 전체가 복구됨을 확인할 수 있을 때만 쓴다.
- 인식할 수 없는 개서: 부분 쓰기 없이 strictFiles 가 pattern_not_found 를 보고한다. 먼저 진단하고 사용자 내용을 덮어쓰지 않는다.

마이그레이션한 파일에는 동작 없는 #90 주석이 붙어, 일반 호스트 업그레이드 검사가 복구된 파일을 새 원본으로 오인해 기존 백업을 덮어쓰지 않게 한다. 반복 적용은 내용을 덧붙이지 않는다. 플러그인 롤백과 호스트 되돌리기는 다른 동작이다. 기존 백업 흐름을 쓰고, 대상과 해시를 대조하며, 사용자가 이후 수정한 설정을 보존한다. 옛 profile 전체로 현재 설정을 덮어쓰지 않는다.

## 테스트

- `test/steer-migration.test.mjs`: 네이티브, 1.1.69, 1.1.71, 옛 포크, 1.6.26, 혼합 상태; LF/CRLF, 반복 적용, 미지 개서.
- `test/steering-runtime.test.mjs`: DSH 0.2.1-rc.2 의 실제 controller, inbox, send, UI steerQueue 메서드를 실행한다. 메모리 서비스와 프로젝션으로 반복 단축키, 지연 갱신, 라운드 상태 전환, 이미 claim 된 상태, FIFO, 편집과 삭제를 모사한다.
- `test/steering-files.test.mjs`: 임시 호스트 디렉터리에서 실제 백업, 쓰기, 재적용, 되돌리기를 수행한다. 사용자 설정 센티널은 그대로 유지된다.

옛 구현은 음성 대조군으로서 고장을 재현할 수 있어야 하고, 새 구현은 같은 시나리오를 통과해야 한다. 픽스처에는 공개 호스트 메서드만 있고 개인 세션, 주소, 프롬프트, 토큰이 없다. 출처와 파일 SHA256 을 픽스처에 기록한다.

`PURGE_TEST_HOST=/path/to/node_modules/@deepseek-ai node --test test/steering-runtime.test.mjs` 로 이 PC 의 메서드를 읽기 전용으로 로드해 메모리에서 마이그레이션한 뒤 실행할 수 있다. DSH 를 기동하거나 재시작하지 않고 모델도 호출하지 않는다. 이것은 함수·프로토콜 수준 실행 테스트이며 전체 데스크톱/모델 인수를 대신하지 않는다.

## #25 확인 목록

보고자는 시스템, DSH 버전, 플러그인 버전을 제공하고, 설치 후 적용과 수동 재실행을 했는지 확인해야 한다. 입력창 직접 끼어들기, 대기열 버튼, 빈 입력창 단축키를 구분하고, 단일인지 연속 조작인지, agent 가 아직 생성 중인지 설명한다. 단일 조작에서도 실패하면 최소한의 일반 작업 재현 절차나 마스킹한 오류 코드가 필요하고, 설정/로그 전체는 필요 없다.

이 버전은 확인된 회귀를 고쳤다. 보고자가 위 정보를 주기 전에는 #25 의 가능한 모든 원인을 해결됨으로 표시하지 않는다.
