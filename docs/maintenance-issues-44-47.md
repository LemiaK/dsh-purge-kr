# 느린 네트워크 업데이트, 설정 합성, 감사 권한(#44 / PR #45–47)

## 업데이트 agent 의 작업 순서

먼저 실패가 버전 조회, 다운로드, 검증, 설치 중 어느 단계에서 났는지 확인한다. 공식 API 에 접근할 수 있다고 해서 release-assets 도메인에도 접근할 수 있는 것은 아니다. 정식 TGZ 는 원래 30초 다운로드 예산을 썼으므로, 모든 실패를 다른 경로의 기본 12초 탓으로 돌릴 수 없다.

1. 기본값에는 설정이 필요 없다: 정식 아카이브 다운로드 총 예산은 180초이며 리다이렉트와 응답 본문을 포함한다. 메타데이터는 여전히 원래 요청 예산을 쓴다.
2. 느린 네트워크에서는 `PURGE_DOWNLOAD_TIMEOUT_MS=300000`(밀리초, 범위 30000–900000)을 설정할 수 있고, 정식 릴리스 아카이브에만 영향을 준다.
3. CONNECT 프록시가 없고 신뢰할 수 있는 URL 접두 서비스가 있으면 사용자가 `PURGE_GH_MIRROR=https://mirror.example/` 를 명시적으로 설정할 수 있다. 여기 주소는 예시이며, 프로젝트가 공개 미러를 내장하거나 자동 선택하지 않는다. HTTPS 기본 포트, 계정·비밀번호·쿼리 문자열·프래그먼트가 없는 접두만 허용한다. 경로가 있는 접두도 지원한다.
4. 이 미러는 커뮤니티 정식 TGZ 만 전송한다. API, 검증 매니페스트, README, 브랜치, 소스 ZIP 은 이 진입점으로 다시 쓰지 않는다. 소스 채널은 1.6.37 이 이 저장소를 가리키도록 고친 수정을 그대로 쓴다. 미러 모드에서는 공식 GitHub API 로 그 release asset 의 SHA256 을 다시 가져온다. 옛 릴리스에 digest 가 없으면 공식 원래 주소에서 SHA256SUMS 를 가져온다. 공식 다이제스트를 얻을 수 없거나, 버전/자산이 맞지 않거나, 바이트 검증이 실패하면 중단한다. 미러가 패키지와 신뢰 근거를 동시에 제공하게 두어서는 안 된다.
5. 변수는 DSH 를 기동한 프로세스가 상속해야 하고, 컨테이너는 자기 서비스 설정에서 지정한다. URL 접두 미러를 `HTTPS_PROXY` 에 넣지 않는다: 후자는 HTTP CONNECT 를 요구한다. 사용자 프록시를 자동으로 바꾸거나 TLS 검증을 끄거나 DSH 를 재시작하지 않는다. 기존 프로세스가 새 환경을 상속하지 않았다면 사용자가 편할 때 직접 다시 시작하기를 기다린다.
6. 다운로드, 다이제스트, 아카이브 신원 점검이 끝난 뒤에야 백업과 설치로 들어간다. 네트워크 실패는 설치 롤백을 실행하지 않는다. 설치 단계 실패는 기존 백업/복원 절차를 그대로 쓰며, 그 때문에 롤백 기능을 끄지 않는다. 캐시 파일은 설치된 상태가 아니다.

이어받기 다운로드는 아직 지원하지 않는다. 진전이 없는 연결도 총 시간 제한을 받는다. 미러가 무효면 명확히 오류를 내고, 서드파티 사이트를 연달아 자동 시도하지 않는다. GitHub Token 은 api.github.com 으로만 보내고 미러에는 보내지 않는다.

## 설정 합성

insert 앞의 같은 이름 `dsh-purge` inject 수정을 삭제하고 insert 안의 완전한 정의를 유지한다. 새 설치에서는 대상을 찾지 못한다는 그 경고가 더 이상 생기지 않고, 이미 있는 사용자 정의 항목은 이 중복 구간에 덮이지 않는다. 사용자의 후행 override 가 여전히 우선하며, 레드팀 옛 패키지 마이그레이션 구간을 삭제하거나 다른 경고를 막지 않는다. 테스트는 실제 호스트 `composeEntries` 를 사용하고, YAML 문자열 단언만 하지 않는다.

## 감사 디렉터리와 실행 사용자

로그 경로를 이전하지 않고, 재귀 chown 도 하지 않고, 사설 디렉터리를 755 로 넓히지 않는다. 새 디렉터리는 700, 새 로그는 600 을 유지하고 기존 권한도 유지한다. root 로 호출된 경우에만 알려진 감사 디렉터리와 `audit.jsonl`, `.1`, `.2` 의 root 소유권을 처리한다. 파일은 하드링크가 없는 일반 파일이어야 하며 심볼릭 링크는 처리를 거부한다. Linux 는 열어 둔 디렉터리와 파일 디스크립터로 수정 대상을 제약하고, 로테이션 후 만들어진 로그도 대상 사용자에게 돌려준다.

- DSH_HOME 이 일반 사용자 소유면 그 UID/GID 를 감사 실행 사용자로 쓴다.
- 컨테이너의 DSH_HOME 자체가 root 소유면 `gosu` 이후의 사용자를 자동으로 알 수 없다. 먼저 읽기 전용으로 서비스의 숫자 UID/GID 를 확인한 뒤, 사용자가 `PURGE_AUDIT_UID` 와 `PURGE_AUDIT_GID` 를 명시적으로 제공한다. 반드시 쌍으로 제공해야 하고, root 소유가 아닌 home 과 지정 UID 가 충돌하면 수리를 중단한다. 사용자 이름을 추측하거나 데이터 디렉터리 전체를 재귀 수정하지 않는다.
- 일반 사용자는 chown 권한이 없다: 플러그인은 권한 상승을 시도하지 않는다. 옛 root 파일은 관리자가 위에 적은 명시적 사용자 컨텍스트로 작업해야 한다. Windows 에는 POSIX 소유권 수리가 없고, macOS 의 교차 사용자 디렉터리 수리는 자동 실행하지 않는다.
- 감사 쓰기가 실패하면 여전히 false 를 반환하고 경고하며 주 작업을 막지 않는다. 읽기가 권한 오류를 만나면 명확히 실패하고, 더 이상 빈 레코드로 위장하지 않는다.

위 수정은 다른 root 소유 백업이나 설정 파일 수리를 보장하지 않는다. 그 경로는 따로 진단해야 하고 이번 감사 수리에 섞을 수 없다.

## 검증과 롤백

회귀는 느린 지속 전송, 정체 타임아웃, 미러 리다이렉트, 공식 다이제스트 불가, 변조 패키지, 다운로드 실패 시 설치/롤백 없음, 설치 후 실패 시 원래 복원 의미 유지를 포함한다. Linux CI 는 실제 root 와 비특권 자식 프로세스로 새 디렉터리, 옛 root 로그, 과거 로테이션, 명시적 컨테이너 UID/GID, 링크 탈출 부정 사례를 커버한다.

세 플랫폼 공식 npm 호스트 인수는 별도 디렉터리를 쓴다: 1.6.36 설치 → 후보 패키지 설치 → 롤백 → 재업그레이드 → 주입 롤백 검증 실패와 복원. 설정과 프롬프트의 원본 바이트를 대조한다. 기존 macOS/Windows Electron 수동 종료 패키지 교체 테스트는 계속 실행한다. 사용자의 DSH 를 기동하거나 재시작하지 않고 모델을 호출하지 않는다.

Windows 공식 npm 호스트 인수에서 8.3 임시 디렉터리 별칭과 긴 경로가 섞여 pnpm store 인덱스 파일명이 너무 길어지는 ENOENT 를 재현했다. 설치 진입점은 실제로 존재하는 아카이브만 native 실제 경로로 해석한다. 전역 pnpm 설정을 바꾸지 않고, 캐시를 지우지 않으며, 백업 신원도 바꾸지 않는다.

롤백 패키지 설치는 기존 Maintenance 스냅샷을 쓴다. 수리된 감사 소유권은 root 로 자동 되돌리지 않는다. 그러면 일반 사용자가 다시 쓸 수 없게 되기 때문이다. 원래 로그 내용과 권한은 삭제되거나 넓혀지지 않았다.

이 버전은 1.6.37 의 출처 수정을 유지한다: beta / 소스 ZIP 채널과 정식 릴리스 채널이 모두 이 저장소를 가리키고, 옛 상수 이름은 호환 별칭으로 남긴다. 소스 ZIP 은 위 TGZ 미러 진입점을 거치지 않는다. 과거 업스트림에 접근할 수 없다고 해서 커뮤니티 정식 버전 업데이트가 막히지는 않는다.
