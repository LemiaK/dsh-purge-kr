# PR #33: 중첩 호스트 위치 판정과 자체 점검 집계

두 가지 레이아웃을 지원한다: 컴포넌트가 `@deepseek-ai/` 에 바로 있거나 `@deepseek-ai/dsh/node_modules/@deepseek-ai/` 에 있다. 사용자는 외곽 scope, `dsh` 패키지 디렉터리, 컴포넌트 루트를 지정할 수 있다.

## 진입점과 컴포넌트를 분리해 해석

- `currentHost()` 는 설치 인스턴스 루트의 기존 의미를 유지한다. 컴포넌트 버전을 읽으려고 설치기가 CLI 를 찾는 루트를 바꾸지 않는다.
- `normalizeHostBase()` 는 선택한 디렉터리와 두 가지 고정 하위 경로만 탐색하며 PATH, 전역 npm, 다른 Desktop, 사용자 디렉터리를 스캔하지 않는다.
- 자체 점검은 명시 경로, `DSH_BASE`, `PURGE_DSH_CLI`, 실행 argv 에 같은 컴포넌트 해석을 쓴다.
- 설치 CLI 는 외곽 scope, 패키지 디렉터리, 그 패키지의 중첩 컴포넌트 루트를 지원한다. 패키지 이름과 bin 경로를 검사하며 임의로 상위를 검색하지 않는다.
- 베어 CLI 에 인스턴스 정보가 없으면 미지로 유지한다. `DSH_BASE` 나 `PURGE_DSH_CLI` 를 지정하며, 다른 설치의 결과를 현재 인스턴스로 계산하지 않는다.

## 집계 기준

자체 점검은 원본 패치 항목 기준으로 센다. 패널에는 합쳐서 표시하는 그룹이 있으므로 두 숫자가 같다고 보장하지 않는다. 숫자를 같게 만들려고 고장을 숨기지 않는다.

- `applied` / `already`: 완료가 확인된 상태.
- `na`, `off`: 명확히 해당 없음이거나 꺼진 상태. 적용 항목 분모에 들어가지 않는다.
- `skipped`: `settleWhenAbsent` 가 마이그레이션이 필요 없다고 명확히 밝힌 경우에만 제외한다. 나머지 건너뜀은 진단을 유지한다.
- `missing_file`: 메타데이터가 선택 사항으로 표시된 경우에만 제외한다. 필수 대상 누락은 이미 있는 명명 계층에 속하지 않은 항목까지 분모를 유지하고 경고한다.
- 미지 상태와 읽기 실패는 성공으로 환산하지 않는다.

모든 판정은 진단에만 영향을 준다. 호스트 패치 표, 프롬프트 정책, 도구 등록, 사용자 권한, 업데이트 선호는 바꾸지 않는다.

## 검증

새 회귀는 먼저 원래 PR 에서 CLI 위치 판정 실패와, 필수 파일이 없는데도 전부 완료로 표시되는 상황을 재현한 뒤 수정을 검증한다. 세 가지 경로, argv/CLI 진입점, 다중 설치 공존, 오류 경로, 탐색 범위 제한, 실제 자체 점검 집계, 미지와 건너뜀 상태를 포함한다.

Windows 실기에서는 새 격리 디렉터리와 profile 로 실제 DSH CLI 를 통해 배포판 설치, 후보 업그레이드, 백업 롤백, 재업그레이드, 설치 후 검증 실패 복구를 수행한다. 실제 Electron/Cordis 로 플러그인 진입점, 명령, 도구, 프롬프트 section, 라우트 등록과 해제를 검증한다. 격리 테스트는 사용자 DSH 를 기동하거나 재시작하지 않고 프록시를 바꾸지 않는다.

후보 테스트 패키지는 `1.6.30-pr33.1` 로 표기하며 격리 검수 전용이고 정식 릴리스가 아니다. 정식 수정은 1.6.30 과 함께 릴리스되었고 PR #33 은 병합되었다.


실측 결과: macOS 전체 테스트 205 항목(200 통과, 5 항목 플랫폼 건너뜀), Windows 11 / Node 22.23.2 전체 테스트 205 항목(201 통과, 4 항목 플랫폼 건너뜀), Electron 44.7.0 통과. 공식 npm `@deepseek-ai/dsh@0.2.1-rc.2` 의 실제 중첩 설치로 세 가지 루트 디렉터리에서 설치, 롤백, 실패 복구를 마쳤다. npm 판 DSH 는 실행 가능한 pnpm 이 필요하다. 테스트는 테스트 프로세스 PATH 에 격리 도구 디렉터리만 추가하며 시스템 PATH 를 바꾸지 않는다.

재현 가능한 실제 CLI 테스트 진입점은 `scripts/verify-rollback-runtime.mjs <baseline.tgz> <candidate.tgz>` 이다. 먼저 대상 DSH CLI 로 새 빈 profile 을 초기화한 뒤 `PURGE_TEST_HOME` / `PURGE_TEST_PROFILE` 과 `PURGE_DSH_CLI` 를 제공한다. 중첩 레이아웃을 검증할 때는 `PURGE_TEST_HOST_BASE` 를 격리 npm 설치의 외곽 `@deepseek-ai` 디렉터리로 지정하고 `PURGE_DSH_CLI` 를 해제한다. 그러면 스크립트가 외곽, 패키지 루트, 컴포넌트 루트로 각각 유지보수를 실행한다. 평소 쓰는 home/profile 을 지정하지 않는다.
