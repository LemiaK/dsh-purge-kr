# 패널 롤백과 업데이트 네트워크 유지보수(1.6.29)

## #34: 패널 롤백의 의존성 누락

`Maintenance.rollback()` 은 과거에 스냅샷을 풀어 DSH 설치 디렉터리에 그대로 넘겼고, 패키지 관리자는 `link:` 를 썼지만 스냅샷에는 `node_modules` 가 없었다. 따라서 설치 명령이 성공해도 플러그인을 로드할 수 있다는 뜻은 아니었다. 1.6.28 이 고친 것은 다른 옛 업데이터의 디렉터리 복구 경로였고 패널 롤백은 커버하지 않았으므로, 그 릴리스 노트를 이 진입점이 검증되었다는 근거로 쓸 수 없다.

이제 스냅샷 검증을 통과한 전체 파일 트리를 `.tgz` 로 묶어 현재 인스턴스의 DSH CLI 로 설치한다. 설치 후 새 프로세스에서 패키지명, 버전, 선언된 의존성 해석, 진입점 import 를 검증해, 호스트 모듈 캐시가 의존성 누락을 가리지 않게 한다. 모듈만 import 하고, 플러그인 apply 를 호출하지 않고, 호스트를 수정하지 않고, DSH 를 기동하거나 재시작하지 않는다.

설치 전에 이번 라운드 profile 의 의존성 그래프, package.json, 잠금 파일을 보존한다. 실패하면 이번 라운드 시작 전 설치 상태로 복구하고, 고장 디렉터리와 백업을 보존한다. 다른 의존성이나 profile 메타데이터의 동시 변경이 감지되면 자동 덮어쓰기를 중단하고 복구가 완료되지 않았음을 명확히 보고한다. 성공하면 임시 의존성 사본을 정리한다. 롤백 중에는 현재 의존성 그래프 하나를 담을 추가 공간이 필요하다. 옛 스냅샷으로 현재 프롬프트, 규칙, 다른 플러그인 설정을 덮어쓰지 않는다.

옛 schema 1/2 스냅샷을 지원한다. "yaml 을 다른 곳에서 링크해 오는" 방식으로 의존성 해석을 대체할 수 없다. 그러면 서로 다른 옛 버전의 의존성이 여전히 맞지 않을 수 있다. Windows Node 22 의 재귀 `fs.cpSync` 는 실기 링크 트리에서 네이티브 종료가 발생했으므로, 임시 그래프 복사를 명시적 순회로 바꾸고 링크를 재귀적으로 따라가지 않는다.

## #35: 두 업데이트 요청 통합

커뮤니티 릴리스 패키지와 옛 업데이트 채널이 `lib/update-http.js` 를 함께 쓴다. TLS, 리다이렉트 화이트리스트, 크기 제한, 전체 타임아웃, 인증, 프록시 선택을 통일한다. 정식 패키지 SHA256 과 옛 ZIP Git tree 검증은 여전히 필수다.

- Token: **호스트 프로세스에 이미 있는 환경** 의 `GITHUB_TOKEN` 을 먼저 읽고, 다음 `GH_TOKEN` 을 읽는다. HTTPS `api.github.com` 으로만 보내고 리다이렉트마다 다시 계산한다. 다운로드 CDN, Atom 페이지, 프록시 CONNECT 로는 보내지 않는다. token 이 없어도 익명 요청을 지원한다.
- 프록시: `PURGE_HTTPS_PROXY` → `https_proxy` / `HTTPS_PROXY` → `http_proxy` / `HTTP_PROXY` → Windows 현재 사용자 정적 시스템 프록시. `no_proxy` / `NO_PROXY` 를 존중한다. `PURGE_HTTPS_PROXY` 를 명시적으로 비우면 이 업데이트 요청은 직접 연결한다. HTTP/HTTPS CONNECT(프록시 인증 포함)를 지원하고 인증서 검증은 유지한다.
- Windows `Internet Settings` 는 **읽기만** 한다. 레지스트리, Clash, 시스템 프록시, 전역 Node Agent, SSH, 사용자 프롬프트, 권한을 바꾸지 않는다. macOS/Linux 는 명시적 환경 프록시를 쓰고, 이 버전은 Linux 설치 진입점을 새로 추가하지 않았다.
- PAC/WPAD 는 실행하지 않는다. PAC 만 설정되어 있고 정적 프록시가 없으면 환경 프록시를 쓰라고 명확히 알린다. SOCKS 는 아직 지원하지 않으며, 설정되면 명확히 오류를 내고 조용히 직접 연결하지 않는다.
- 환경 변수는 DSH 를 기동한 프로세스 환경에 있어야 한다. 다른 터미널에서 설정해도 실행 중인 데스크톱 프로세스는 바뀌지 않는다. 언제 수동으로 다시 열지는 사용자가 정하며 자동 재시작하지 않는다. token 을 issue, 스크린샷, 로그, 공개 설정에 쓰지 않는다.
- 403 이 항상 레이트 리밋은 아니다: rate-limit 응답 헤더와 함께 할당량 소진, 인증/권한, 404, 연결 오류, 타임아웃을 구분한다. 할당량이 소진되면 재설정 시간을 표시한다. Atom 강등 실패와 옛 목록 사용은 모두 보이게 설명하고, 옛 목록을 "최신 확인됨"이라고 부르지 않는다.
- 독립 bootstrap 설치 스크립트는 플러그인 로드 전에 실행되며 여전히 자체 포함 다운로더다. 이 절의 환경 프록시 호환 계층은 플러그인 안 업데이트 요청에 해당하고, 옛 호스트나 모든 다운로드 도구가 개조되었다고 주장할 수 없다.

## 인수 요구 사항

1. 임시 DSH_HOME/profile 에서 실제 DSH CLI 로 공개 1.6.28 을 설치한다. 옛 패널 롤백이 link 를 만들고 의존성 누락을 재현한다.
2. 새 설치기가 손상된 링크를 복구하고, 새 패널이 옛 스냅샷을 롤백하고, 다시 업그레이드한다. 각 단계에서 새 프로세스로 진입점을 import 한다.
3. 실제 설치가 끝난 뒤 검증 실패를 한 번 주입해 package.json, 잠금 파일, 원래 버전 의존성, 진입점이 복구되는지 확인한다.
4. Windows 4090 실기에서 위 흐름과 자동 테스트를 실행한다. 원래 설정 파일과 프록시 레지스트리 다이제스트를 비교하고, 실행 중인 DSH 는 조작하지 않는다.
5. 로컬 임시 HTTPS 서비스와 CONNECT 프록시로 실제 TLS, 프록시 인증, 교차 출처 token 격리, 응답 한도, 전체 타임아웃을 검증한다. 테스트 CA 는 테스트 자식 프로세스 환경으로만 로드하고 시스템 인증서 저장소에 넣지 않는다.
6. 릴리스 전에 실제 산출물, 테스트 결과, 검증 기록을 보관한다. Node/Electron import 와 서비스 등록 검증은 사용자 데스크톱 GUI 전체 인수와 같지 않다.

재사용 가능한 실측 진입점: `scripts/verify-rollback-runtime.mjs`. 새로 만든 격리 profile 만 쓰고, `PURGE_TEST_HOME`, `PURGE_TEST_PROFILE`, `PURGE_DSH_CLI` 를 명시적으로 설정하고, 옛 버전과 후보 버전 tgz 를 넘긴다. 일상 사용자 profile 을 테스트 픽스처로 쓰는 것은 금지한다.
