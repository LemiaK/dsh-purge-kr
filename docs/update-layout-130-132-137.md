# #130 / #132 / #137: 설치 위치 판정, 미러와 마켓 검수

2026-11-05, 1.6.75. **유지보수자는 Windows 전체 트랜잭션 검수가 Defender 차단으로 막혀 있음을 인지하고 배포를 명시적으로 승인했다; 이 제한은 여전히 해결되지 않았다.**

## 수정 범위

- #130: 같은 앱의 옛 Desktop CLI 와 `@deepseek-ai/dsh` manifest bin 을 경계 있게 읽는다; 새 셸의 Node wrapper, 내장 pnpm, 잠금 복구 runner 를 그대로 쓴다. 없거나 범위를 벗어나면 오류를 내고, 작업 공간이나 profile, 사용자 디렉터리를 스캔해 다른 설치를 고르지 않는다. 설치기는 옛 desktop 과 새 web 기본 profile 을 구분하고 사용자 정의 profile 을 보존한다.
- 아카이브 안의 버전은 읽기 전용 진단 증거이며 쓰기 가능한 경로가 아니다. 미언팩, 컴포넌트 누락, 혼합 버전을 각각 보고한다. 이미 손상된 app 디렉터리를 아카이브의 건강한 파일로 대신하지 않는다.
- #132: 미러 설정을 영속화하고 메타데이터 조회와 다운로드에 일관되게 쓴다. 미러와 그 리다이렉트 체인에는 Token 을 보내지 않는다. 설치는 이 저장소의 공식 릴리스 URL, 공식 digest, SHA256, 패키지 신원 검증을 고수하며, 공식 digest 에 도달할 수 없으면 계속 오류를 낸다.
- #137: 인덱스가 릴리스별 호환 범위를 읽는다. 선언이 없는 옛 버전은 옛 범위를 유지하며, 사용자 호환 예외를 수정하지 않는다.

호스트 패치 정의, 프롬프트 내용, 사용자 권한은 수정하지 않았다. 모델 우회 능력을 테스트하거나 주장하지 않는다. 정식 DSH 설정, 프록시, 프로세스는 건드리지 않았다.

## 검증

- 기본 Node 회귀: 553건, 532 통과, 조건부 건너뜀 21, 실패 0.
- 패널 테스트: 29건 통과; 커뮤니티 bundle, 포맷, 버전, 배포 패키지 import 점검 통과.
- Mac CLI 전용 격리 Electron: 실제 CLI/pnpm 최초 설치, 1.6.74 업그레이드, 옛 의존성 별칭 마이그레이션, 백업, 롤백, 재업그레이드, 설치/롤백 실패 복구 통과. 백업 후 추가된 사용자 내용이 보존되는지 확인했다. OS 샌드박스가 정식 앱, 사용자 DSH home, 로그 디렉터리 쓰기를 막는다.
- Windows 원본 설치 패키지: DSH Desktop 0.13.2 / 커널 0.2.2-alpha.2; 설치기에서 추출했고 GUI 를 설치하거나 기동하지 않았다. SHA512 가 릴리스 메타데이터와 일치하고 Authenticode 는 Valid 였다. 실제 Electron 에서 CLI 위치 판정, 아카이브 버전 진단, web profile 초기화, 번들 pnpm/runner `--version` 이 통과했다.
- Windows 격리 Electron 컴포넌트/실제 TLS 테스트 43건 통과; Mac 격리 Electron 의 위치 판정/미러/실제 TLS 대응 테스트 24건 통과.
- Windows Node 전체 회귀 통과(플랫폼 조건 항목은 선언대로 건너뜀), PowerShell 5.1 래퍼 컴포넌트 테스트 통과; 이 두 항목이 실제 설치를 대신할 수 없다.
- Windows **전체 설치 실패**, 따라서 업그레이드와 롤백의 최종 검수는 아직 통과하지 못했고 위 항목으로 대신할 수 없다.
- Mac 공개 미러 실측: 명시적 `https://gh-proxy.org/` 로 릴리스 목록을 조회하고 기존 1.6.74 를 내려받아 독립 공식 digest 와 패키지 검증을 통과했다. 테스트에는 Token 을 넣지 않았다. 미러 가용성은 이번 관측일 뿐 서비스 보장이 아니다.
- 실제 DSH 0.2.2-rc.1 의 `evaluatePluginCompatibility`: 생성된 1.6.74 인덱스는 rc.1 을 수용하고 0.3.0 은 계속 거부하며, 역사적 릴리스 기록 66개를 각각 처리한다.

위 설치 점검은 모델을 기동하지 않고 apply 를 호출하지 않았으며 호스트 서비스를 시작하거나 GUI 마켓을 클릭하지 않았다; 의존성 캐시가 재사용되었을 수 있으므로 네트워크 전체 콜드 설치라고 할 수 없다.

## Windows 장애: 실제 실패를 그대로 남긴다

첫 실제 설치에서 래퍼가 요구하는 패키지 관리자 환경이 전달되지 않는 문제를 발견해 고쳤다. 이어서 새 profile 의 pnpm add 가 `ERR_PNPM_UNKNOWN` 을 반환했고, 구체적으로는 store 파일 열기 실패였다. Defender 탐지 기록을 읽어 같은 테스트에서 격리가 일어났음을 확인했다:

- 탐지 이름: `Backdoor:PHP/Chopper.E!dha`, ThreatID `2147891541`.
- 릴리스 패키지의 기존 파일: `skills/redteam/unauth-exploit.md`.
- 이 파일의 SHA512: `96bce1192f61f904f9ce13e95e2afd0fd75ddffe4cba022e1de01f61ad592e4f87f949bfe74f06c07afe34215c8e62aa750dce58be5765eda389bfea4a706506`, pnpm store 대상과 일치.
- 이 파일의 SHA512 는 배포된 1.6.74 와 후보 패키지에서 완전히 같았고 이번에 수정하지 않았다. 이전 캐시 재사용 경로에서 한 번 성공한 것이 새 설치나 문제 해소를 증명하지 않는다.
- 실패한 설치 보고는 이전 의존성/매니페스트를 복구하고 스냅샷을 보존했다; 이 관측이 전체 업그레이드/롤백 매트릭스 통과를 뜻하지 않는다.

보호 기능을 끄거나 화이트리스트를 추가하거나 파일을 삭제·인코딩·이름 변경해 탐지를 피하지 않았고, Microsoft 에 파일을 제출하지도 않았다. 격리 로그를 보존했으며 현재 오탐이라고 단정할 수 없다. 유지보수자는 위 실측 결과를 검토한 뒤 병합 배포를 명시적으로 요구했다. 릴리스 노트는 이 미통과 실기 검수를 남기며, 배포 승인을 고장 수리나 전체 검수 통과와 동일시하지 않는다.

## 재현 진입점

`check-update-layout-runtime.mjs` 는 격리 fixture 표식이 있는 Electron Node 모드로 실행해야 하며, 인자는 fixture 루트, 해당 fixture CLI, 배포된 기준 TGZ, 후보 TGZ 다. Mac 은 정식 .app 런타임을 금지하고 쓰기 제한을 건다. 스크립트는 실제 설치 트랜잭션을 수행하며 profile 이나 동의 기록을 위조하지 않는다.

`test/desktop-cli-130.test.mjs` 는 새/옛 디렉터리, manifest 범위 초과, 무관한 작업 공간/홈 디렉터리, 공유 resolver, pnpm 경계를 다룬다; `test/update-mirror.test.mjs` 는 출처 거부, Token 격리, 리다이렉트, 권위 digest 실패, 옛 선호 보존을 다룬다. 컴포넌트 테스트는 실제 전체 트랜잭션을 대신하지 못한다.

REA 정적 증거 `ev_3087f8712b65694554ba319dc8aae1add4d0d7ecbccb294943cd9d7ab8702015` 는 추출된 packaged-pnpm-invocation 모듈을 구문 분석한다; 정적 결과가 실행 성공을 증명하지는 않는다. 패키지 내부 wrapper/main 의 일반 소스 읽기와 위 실제 자식 프로세스 테스트가 함께 요구 환경 계약을 확인한다.
