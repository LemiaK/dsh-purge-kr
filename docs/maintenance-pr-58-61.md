이 버전은 독립 수정 커밋을 쓰고, 원 PR 을 닫지 않으며, 네 제안이 완전히 구현되었다고 선언하지 않는다.

| #60 | 업스트림 전파 취소, 전송 완료/실패/취소만 기록 | 거부 감지 확대와 재시도 문구 수정 미병합 |
| #61 | 설정 감사 통일, retry 적용 설명 정정 | 새 inject CLI 쓰기 진입점 미병합; rewind 는 여전히 UI 재로드 필요 |

심사에서 발견한 것: #58 의 기본 강화 섹션도 정렬 변경에 영향을 받으므로, 호스트 상수를 복사한 테스트만으로 호환성을 증명할 수 없다. #59 의 비앵커 매칭은 본문에 걸린다. #60 의 새 항목은 정상적인 기술 논의에 걸린다. #61 의 rewind 즉시 적용 설명은 프런트엔드 캐시와 맞지 않는다. 원 PR 을 유지해 이 미해결 항목들을 계속 논의할 수 있게 한다.

loLollipop 의 제안과 문제 단서에 감사한다. 이번에는 기존 탐지 패턴, 재시도 프롬프트, 기본 스위치, 호스트 패치 표를 수정하지 않는다.

## 재현 가능한 문제

격리된 1.6.41 소스 사본에서, 일반 문장에 옛 표식이 들어가면 뒤따르는 텍스트가 잘렸다. 소비자가 일반 출력을 취소하면 업스트림 생성기의 finally 가 실행되지 않았다. 설정을 직접 쓰면 감사 항목이 생성되지 않았다. 같은 입력에 대해 새 회귀는 본문 전체 보존, 업스트림 종료, 실제 설정 변경만 한 번 기록할 것을 요구한다.

옛 분할 동작은 여전히 구조적 표식을 경계로 한다. 이번에 보호하는 것은 비구조적 본문과 예시이며, 임의의 사용자 문서를 자동으로 이해한다고 주장하지 않는다. 표식은 여전히 코드 펜스 밖에 있고, 들여쓰기가 없고, 한 줄 전체를 차지하는 옛 버전 대문자 텍스트여야 한다.

## 상태와 로그 의미

- `tuning_setting` 은 알려진 스위치와 열거의 유효한 변경만 기록한다. 무효 타입은 `invalid` 로 표시하고 임의 문자열이나 객체를 감사에 복사하지 않는다. 미지 필드는 설정에 원래대로 저장한다.
- 쓰기 실패는 성공 기록을 만들지 않는다. 감사 자체의 실패는 기존 경고를 따르고, 설정 저장과 출력 스트림의 결과를 바꾸지 않는다.
- `refusal_retry_outcome` 은 원본 스트림이 끝난 뒤 전송 유형을 기록하며, 답변 정확성, 작업 성공, 모델 동작의 판정 근거가 될 수 없다.
- `text`, `tool_call`, `reasoning_only`, `empty` 는 출력 형태를 구분하고, `error`, `cancelled` 는 예외와 소비자 취소를 구분한다. 늦게 도착한 오류를 미리 성공으로 기록하지 않는다.
- 새 스트림 진단은 본문, 추론 내용, 도구 인자, 오류 원문, URL 을 기록하지 않는다.
- retry 는 다음 요청에서 설정을 읽는다. rewind 의 프런트엔드 가시성 캐시는 여전히 재로드를 요구한다. 플러그인은 자동 재시작하지 않는다.

## 검증 방식

`test/review-integrity.test.mjs` 는 일반 기술 답변의 청크 단위 보존, 추가 요청 미발생, 일반 본문/인용/코드 펜스 보호, 소비자 취소, 늦은 오류, 동기 생성 오류, 도구 호출 스트림, 순수 추론 스트림, 출력 없음, 감사 실패, 실제 CLI 자식 프로세스, 반복 저장, 쓰기 실패, 미지 설정 보존을 커버한다.

그중 HTTP 케이스는 127.0.0.1 만 수신하는 서버를 실제로 기동하고, 첫 청크를 소비한 뒤 취소하며, 서버 연결이 닫혔음을 단언한다. 테스트는 외부 모델을 요청하지 않고 사용자 profile 을 건드리지 않는다.

전체 회귀와 세 플랫폼 설치/롤백 워크플로는 계속 실행한다. 자동화된 스트림 테스트는 실제 모델 품질 평가가 아니며, npm 호스트 설치 인수도 세 플랫폼 전체 UI 기능 인수와 같지 않다.
