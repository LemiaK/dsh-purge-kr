# 1.6.4

Web / Headless 유지보수 수정 버전이며 [PR #4](https://github.com/kingcharleslzy-ai/dsh-purge/pull/4) 를 병합하고 [issue #3](https://github.com/kingcharleslzy-ai/dsh-purge/issues/3) 을 해결한다.

## 무엇을 고쳤는가

- **백업 목록이 새로고침 후 비어 있음**: 유지보수 페이지에 들어가거나 다시 열면 백업을 자동으로 읽고, 새로고침 진입점을 추가하며, 로딩 중 / 읽기 실패 / 백업 없음을 구분한다; 롤백 대상을 자동으로 선택하지 않는다.
- **실패가 성공으로 오보됨**: HTTP 200 안의 `ok:false` 를 올바로 식별하고 백업, 업데이트, 롤백 결과와 부분 업데이트 상태를 각각 표시한다; "백업 생성됨: undefined" 가 더 이상 나오지 않는다. 유지보수 실패 후 이미 만들어졌을 수 있는 복구 스냅샷을 다시 읽고, 쓰기 작업을 자동 재시도하지 않는다.
- **업데이트 후 로딩 안내가 불명확함**: 설치 성공 시 버전을 표시하고 서버 DSH 프로세스를 재시작해야 함을 명확히 알린다; 브라우저만 새로고침하면 새 백엔드가 로드되지 않는다.
- **npm CLI / profile 위치 판정 불완전**: 유지보수, 설치, 읽기 전용 자체 점검이 현재 인스턴스 해석 로직을 공유한다; npm CLI 는 현재 패키지가 선언한 bin 에서 위치를 찾고 `PURGE_DSH_CLI` 명시적 덮어쓰기를 유지한다. 심볼릭 링크를 지원하며 정확한 DSH_HOME/profile 을 전달하고 다른 전역 설치를 추측하지 않는다; 충돌하거나 확정할 수 없으면 명확히 오류를 낸다.
- **Web 자체 점검이 다른 Desktop 을 잘못 검사함**: Web 의 app.asar 검사는 "해당 없음"으로 표시하고 레이아웃 실패로 세지 않는다; Desktop 은 대상 자신의 리소스 디렉터리만 검사하며 읽을 수 없거나 대상이 미지일 때 성공으로 오보하지 않는다.

이번 변경은 권한 선택, 프롬프트, 패치 표, 백업 정리 정책을 바꾸지 않는다. 릴리스는 사용자 대신 로컬 DSH 를 설치하거나 재시작하지 않는다.

## 설치 패키지와 업그레이드

첨부에 `dsh-purge-community-1.6.4.tgz` 와 `SHA256SUMS.txt` 를 제공하므로 검증 후 설치한다. 기존 사용자는 플러그인 유지보수 페이지에서 이 버전 업데이트를 선택할 수 있다; 설치를 마친 뒤 DSH 프로세스를 직접 재시작한다. 유지보수 위치 판정과 환경 변수 설명은 [Web / Headless 문서](https://github.com/kingcharleslzy-ai/dsh-purge/blob/v1.6.4/docs/WEB-MAINTENANCE.md) 를 본다.

## 검증 범위

- 백엔드 테스트 52건 통과, 인스턴스 해석, CLI 인자, 격리 테스트 15건 포함.
- 패널 기존 테스트와 신규 유지보수 상호작용 테스트 6건 통과; 릴리스 클라이언트 리소스를 다시 빌드했다.
- 빌드 일관성, 문서 버전, 모듈 import, 릴리스 패키지 smoke 검사 통과.
- npm CLI 실행 테스트는 임시 디렉터리의 통제 가능한 진입점을 썼으며, 실제 Linux Web 서비스나 전체 호스트 패치의 엔드투엔드 검수를 완료했다고 주장하지 않는다.
