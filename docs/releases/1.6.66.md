# 1.6.66

## 수정 내용

- 일부 Electron 데스크톱 셸이 `--updated` 만 붙여 기동될 때 패널이 현재 호스트를 찾지 못하는 문제를 수정한다. 읽기 전용 진단은 현재 프로세스의, 패키지 신원이 검증된 리소스 디렉터리로 제한한다; 설치와 쓰기 대상 선택은 변하지 않는다.
- Electron 의 실제 앱 진입점 증거를 쓴다. 미지, 읽기 실패, 인스턴스 교차 상황에서 더 이상 "패키지 교체 완료"를 잘못 표시하지 않는다; 실제 누락 컴포넌트는 계속 보고한다.
- Windows 패키지 교체가 백업 충돌, 권한 등 모든 이동 실패를 "잠금 대기"로 취급하지 않는다. 공유/잠금 충돌은 계속 대기하고, 나머지 실패는 원인과 오류 코드를 표시하며 원본 아카이브와 기존 백업을 보존한다.
- 유지보수 페이지와 CLI 의 호스트 버전 진단이 같은 위치 판정 근거를 쓴다. 독립 CLI 에 인스턴스를 지정하지 않으면 명확히 안내하고, 위치 미판정을 플러그인 미설치로 보지 않는다.

## 검증과 범위

- PR #121 의 GitHub 검사가 모두 통과했다: Mac, Windows, Linux 설치와 공식 npm 호스트 업그레이드, 롤백, 실패 복구 포함.
- 이 PC 회귀: 409건 통과, 13건 플랫폼/선택 조건 건너뜀; UI 테스트 26건 통과.
- Mac 과 Windows 11 의 격리 Electron 44.7.0 실측: `--updated` 만 붙은 데스크톱 셸이 자기 호스트와 실제 진입점을 식별했다; 설치기 대상 선택은 변하지 않았다.
- Windows 실제 파일 점유가 오류 32 를 반환하고, 해제 후 정상적으로 패키지를 교체했다; 백업 대상이 이미 있으면 오류 183 을 반환하고 명확히 실패하며 두 파일을 보존했다. 패키지 교체 도우미는 런처가 종료된 뒤에도 계속 대기하고 완료할 수 있었다.
- 프롬프트, 설정, 기존 기능, 업데이트 선호는 변하지 않는다; 이번에 유지보수자의 정식 DSH 에 설치하지 않고 자동 재시작하지도 않는다.

#118 은 열린 상태로 둔다: 재현해 수정한 것은 오류 분류 문제이며 이것으로 보고자가 겪은 구체적 멈춤 원인을 단정할 수 없다. 여전히 해당 사용자의 패키지 교체 상태, 오류 상세, 도우미 로그가 필요하다. #119 의 수정은 호스트 진단에 한정되며 #102 가 말한 NEXT 데스크톱 배포판이 완전히 호환된다는 뜻이 아니다.
