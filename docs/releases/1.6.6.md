# 1.6.6 설치 수정 검수

이번 변경은 설치, 아카이브 경로 호환, 문서만 고친다; 호스트 패치, 사용자 프롬프트, 규칙, 업데이트 선호는 바꾸지 않는다.

- [세 플랫폼 CI](https://github.com/kingcharleslzy-ai/dsh-purge/actions/runs/39096529198): Linux/macOS/Windows 설치기와 유지보수 사례 통과; Windows 는 PowerShell 5.1 과 PowerShell 7 진입점 테스트를 실행한다. Windows 의 POSIX shell 전용 테스트는 명확히 건너뛰었고 Windows chmod 를 POSIX 권한 검증으로 취급하지 않았다.
- Node 기능 회귀 89건, 패널 테스트 7건, 원시 진입점 계약, 빌드 일관성, 문서 버전 검사, 릴리스 패키지 smoke 통과.
- 실제 npm 공식 메타데이터: `@dsh-ops/bash-win32-x64@0.2.1` 의 신원, 버전, 배포 시각, integrity, tarball 검증에 성공했다; 모의한 정확한 미러 버전 누락 오류 이후에만 scope 단위 재시도를 한 번 허용한다.
- Mac 에서 설치된 DSH Desktop 의 실제 Electron 과 CLI 로 독립 DSH_HOME/profile 에서 다운로드 검증, 패키지 마이그레이션, 백업, 롤백을 수행했다; 테스트 설정은 유지되었고 백업 후 새로 고친 프롬프트도 롤백에 덮이지 않았다. 실제 DSH 를 재시작하지 않았고 사용자의 실제 profile 을 수정하지 않았다.
- Windows 는 실제 tar/Node 하위 프로세스, 중국어와 공백이 있는 상위 디렉터리, 인자 전달, 비정상 종료, 다운로드 실패, 환경 복구를 커버한다; 이 결과를 전체 Windows DSH UI/호스트 패치 검수라고 주장하지 않는다.

알려진 경계: DSH 마켓 최초 설치는 플러그인 로드 이전에 일어나므로 이 버전이 그 오류 분류를 넘겨받을 수 없다. npm 공식 소스를 고르거나 독립 PowerShell 진입점을 쓴다; 공급망 검사를 끄거나 잠금 파일을 삭제하라고 요구하지 않는다. Issue #7 은 원 제출자가 자기 환경을 확인할 때까지 열어 둔다.

이후 공개 다운로드 진입점 검증에서 macOS 임시 디렉터리 별칭 때문에 bootstrap 이 조용히 실행되지 않는 문제가 발견되었다; 수정된 [1.6.7](1.6.7.md) 을 사용한다. 이전 격리 라이브러리 함수 호출 통과는 shell 다운로드 진입점 통과를 뜻하지 않으므로 독립 진입점 회귀를 추가했다.
