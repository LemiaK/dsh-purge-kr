# 1.6.39

- #52 독립 설치기가 `fetch failed` 만 표시하고 실패 단계를 특정하지 못하는 문제를 수정한다: 이제 버전 조회/아카이브/검증 매니페스트, 공식 도메인, 다운로드 채널, 시도 횟수, 저수준 오류 코드를 표시하고 프록시 자격 증명과 서명 URL 은 가린다.
- 일시적 네트워크 오류와 일부 임시 HTTP 오류는 먼저 한 번 재시도하고, 그래도 실패하면 시스템 curl 을 시도한다; 총 횟수와 대기 시간에는 상한이 있고 시스템/사용자 프록시는 바꾸지 않는다.
- 두 채널 모두 홉마다 공식 HTTPS 출처와 크기를 검증한다; 인증서, SHA256, 패키지 신원 검증을 유지하고 영구 오류는 무작정 재시도하지 않는다. 다운로드나 검증이 실패하면 설치로 넘어가지 않는다.
- 실제 curl/TLS/CONNECT 테스트, 장애 주입, 리다이렉트 경계, 무효 인증서, 잘림/과대 응답, 타임아웃, 설정 보존 테스트를 보강한다; 선택한 Node/Electron 런타임에서 실제 GitHub 다운로드 검수 스크립트를 추가한다.

기존 프롬프트, 설정, 프리셋, 기능, 프록시는 바꾸지 않고, 패치를 자동 적용하거나 DSH 를 종료/재시작하지 않는다. #52 보고자의 구체적 네트워크 고장은 새 버전의 민감정보 제거 로그로 확인해야 하며, 이 PC 의 통과를 상대 환경 복구로 볼 수 없다.

조사와 테스트 경계는 [유지보수 안내](https://github.com/kingcharleslzy-ai/dsh-purge/blob/master/docs/maintenance-issue-52.md) 를 본다.
