# Purge Community 1.6.13 검수 기록

## 문제와 수정

DSH Desktop 0.2.1-rc.2 의 tool-subagent 가 옛 toolFilter 인자를 거부한다. 자동 관리 표식이 없는 옛 unrestricted 파일은 업데이터가 올바르게 보존했지만 새 등록 프로토콜로 마이그레이션되지 않아 실제 프리셋 로드 실패가 발생했다.

이 버전은 사용자 정의 YAML 을 덮어쓰지 않는다. 등록 전에 원본 agent.cordis.yml / preset.yml 을 SHA256 목록과 함께 사설 콘텐츠 주소 백업으로 저장한다; 그다음 메모리에서 표현 가능한 spawn deny 정책을 원시 하위 프리셋과 agentPreset 참조로 변환한다. 상위 프리셋은 이 정책 설정 한 곳만 교체하고 나머지 프롬프트, 도구 행, 깊이 제한, 표현식, 사용자 설정은 그대로 유지한다. 하위 프리셋은 설정을 상속하고 원래 deny 목록의 도구만 제외한다. 설정 페이지에 위임용 "무제한 모드 · 서브태스크"가 하나 추가된다.

현재는 단일 spawn deny 목록을 지원한다; 미지 도구, allow, 여러 정책, 이미 존재하는 독립 agentPreset 의 의미를 추측하지 않는다. 이런 설정은 중단하고 진단한다. 새 설치도 원래 서브태스크 도구 정책을 유지한다. 기존 호스트 패치 83건은 수정하지 않았고 패치를 자동 적용하거나 앱을 재시작하지 않는다.

## 완료된 검증

- Node 자동 테스트 121건: 116 통과, Windows 전용 5건은 플랫폼에 따라 건너뜀, 실패 0.
- 이 PC 의 실제 Desktop Electron 44.7.0, DSH 0.2.1-rc.2, 원시 Loader / AgentPresetRegistry: 격리 home 에서 같은 옛 프리셋의 원 오류를 먼저 재현한 뒤 상위/하위 프리셋 로드에 성공했다.
- 원시 Agent 팩토리로 빈 상위/하위 세션을 만들고 모델이 보는 도구를 확인했다: 상위 세션은 subagent_fork / workflow / ralph 를 유지하고 하위 세션은 이 세 도구를 제외하며, 양쪽 모두 subagent 와 skill 을 유지한다. LLM 요청은 보내지 않았다.
- 실제 Cordis 플러그인의 반복 로드 및 제거 테스트에서 기존 disposer 가 생애주기에 결합되지 않은 문제를 발견해 수정했다; 이제 상위/하위 선언이 완전히 회수되고 반복 로드가 같은 백업을 재사용하며 원본 사용자 정의 파일 바이트는 변하지 않는다.
- 단위 테스트가 상위 설정의 정확한 동등성, 프롬프트 보존, 미지 정책 중단, 손상된 스냅샷 거부, 실제 활성화 오류 회수, 중복 dispose 를 커버한다.

이번에 Windows 전체 기능 실기 검수를 완료했다고 뭉뚱그리지 않았다; 크로스 플랫폼 파일 작업은 CI 가 검사한다. 실행 중인 이 PC 의 DSH 는 설치기가 자동 재시작하지 않는다. 소스/릴리스 패키지에 사용자 설정이나 사설 백업은 포함되지 않는다.
