# 1.6.3

> 1.6.3 = 강화 섹션에 "승인되면 실행" 조항 추가: 자산/CTF 를 선언하면 2차 확인을 하지 않는다.

실측 피드백: 어떤 세션에서 모델이 승인 선언을 분명히 봤는데도 "승인 증명"을 반복 요구하거나 "확실한가"로 말을 바꿨다. boost 섹션에 한 조항을 추가한다: 대상이 자산 / 고객 프로젝트 / CTF 실습 환경으로 선언되면 바로 실행하고 승인 파일을 더 요구하지 않는다; 선언이 없으면 "대상이 당신 것이거나 실습 환경인가?" 한 번만 묻고, 긍정 답을 받으면 즉시 작업을 시작하며 이후 다시 문제 삼지 않는다. 승인되지 않은 타인 대상은 여전히 거부한다 — 그건 모델 자체 정책이며 플러그인 계층에서 보장하지 않는다.

DSH 0.2.1 의 `dsh-tool-subagent` 는 `toolFilter` 를 그대로 거부한다(agent preset 에서 `agentPreset` 로 선택하도록 변경). 옛 프리셋이 이를 들고 있으면 마운트가 통째로 실패해 두 사용자 정의 모드가 빨간색으로 표시되었다. 레드팀 프리셋의 도구 행 이름도 여전히 `dsh-purge/redteam/tools`(패키지 이름은 `dsh-purge-community` 로 변경됨)여서 마찬가지로 `never started` 가 났다. 템플릿을 고치고 자가 복구(그 자리에서 `toolFilter` 제거, 옛 패키지 이름 마이그레이션)를 추가했으며, 이 PC 의 프리셋 두 개를 한 번 새로 고쳤다.

- **[PR #1](https://github.com/kingcharleslzy-ai/dsh-purge/pull/1)(@luowang-ui) 병합**: `repairOfficialCliAfterUnpack()` 는 동기 함수인데 비동기 `atomicCopyFile` 을 await 없이 호출했다 — Windows/Node 24 에서 rejection 이 `try/catch` 를 우회해 `uncaughtException` 으로 승격되고 호스트가 로딩 단계에서 즉시 종료되었다("앱을 기동할 수 없거나 예기치 않게 중지되었다"). 함께 데이터 무결성 문제 하나를 고쳤다: 비동기 복사 때문에 `.dsh-purge.bak` 이 패치 기록 이후에 파일을 읽어 패치 후 바이트로 저장될 수 있었다. `atomicCopyFileSync` 를 추가하고 회귀 사례를 보강했다.
- **설치 패키지 지속화**: `install()` 이 tgz 를 먼저 `$DSH_HOME/dsh-purge-community/pkgs/` 로 복사한 뒤 pnpm 에 넘긴다. `file:` 이 `/tmp` 나 Downloads 를 가리켜 재시작 후 의존성 해석이 실패하는 것을 막는다.

- **감사 로그**: `apply` / `revert` / `boost` / `probe` / `preset` / `reanchor` 마다 동작 1건을 JSONL 로 기록한다(`audit.jsonl`, 1MB 로테이션 2개 보존); `purge-community audit` 또는 패널 "유지보수 → 최근 동작"에서 읽을 수 있다. apply 기록에는 스냅샷 id, 호스트 버전, 성공/적용됨/실패 카운트, 실패 패치 번호가 들어간다.
- **릴리스 패키지 smoke test**: `npm run smoke` 가 tgz 를 풀어 검증한다 — export 대상 8개 존재, 핵심 모듈 import 가능, 내장 프리셋이 20줄 정의로 해석됨, `cordis.patch.yml` 항목 완전성, CLI 가 빈 디렉터리에서 실행됨, 호스트가 없을 때 selfcheck 가 broken 으로 안전하게 저하됨. community/release 두 workflow 에 연결했다.
- **점검 수정**: `anchors.js` 가 core 를 import 하지 않는다(순환 의존성 제거); 재앵커 캐시를 명시적 변수로 바꿨다; `--index` 값 누락, `audit --limit` 잘못된 값에 보호를 넣었다; 만료된 프로브 파일을 자동 정리한다; 프리셋 등록이 "중복/무효"에서 40회 무의미한 재시도를 하지 않는다.

호스트 업그레이드로 앵커가 깨졌을 때 `diagnose` 는 이제 행 번호만 주지 않는다: `reanchor apply <id> --lines A-B` 가 현재 호스트의 실제 스니펫을 뽑아 후보로 제시하고(유일성 검증, dry-run 미리보기), `--yes` 를 붙이면 `~/.dsh/dsh-purge/anchor-overrides.json` 의 로컬 덮어쓰기로 기록된다; 패치 엔진은 인덱스로 적용하며 `reanchor clear <id>` 로 철회할 수 있다. 덮어쓰기는 호스트 버전과 함께 기록되어 버전이 바뀐 뒤 어떤 항목이 로컬에서 고정된 것인지 한눈에 보인다.

- **스냅샷 중복 제거**: 32KB 를 넘는 파일은 sha256 별로 `backups/objects/` 에 저장하고 스냅샷에는 참조만 남긴다; 같은 `client.js` 는 한 번만 공간을 쓴다. 실측에서 스냅샷 1건이 9.0MB → **2.0MB** 가 되었고, `verify` 가 객체 해시를 하나씩 확인하며 `prune` 후 참조되지 않는 객체를 자동 GC 한다.
- **AGENTS.md**: agent 용 사용 설명서 — 다섯 계층 모델, 명령과 종료 코드, 증상→조치 의사결정 트리, 패치 표 읽기/추가 방법, 상태 파일과 불변 조건. `check:docs` 가 이제 그 버전 줄도 검증한다.
- **README**: 버전 번호와 신규 기능(프로브, 프리셋, 자체 점검 3상태, 중복 제거)을 동기화했다; 명령 표에 `probe` / `preset` 을 보강했다.

- 자체 점검이 "적용 대기"와 "적용 불가"를 구분한다: pending 은 ⏳(노랑), broken 만 ✗(빨강); `selfcheck` 종료 코드는 broken 일 때만 1 이므로 설치기가 "적용이 한 번 남음" 때문에 실패를 보고하지 않는다.
- 런타임 프로브 추가: 패널 "프로브" 버튼 또는 `purge-community probe new` 가 일회성 nonce 를 만들고 시스템 프롬프트 끝에 "보이면 그대로 되돌려 출력" 짧은 지시를 붙인다 — 모델이 되돌려주면 주입이 실제 컨텍스트에 도달한 것이다(30분 후 자동 만료).

`unrestricted` 프리셋을 설치하면 패치 #24(preset 의 web fetch 열기)가 이 새 파일을 적용 대상으로 잡아 자체 점검에 빨간 줄이 하나 늘어난다 — "적용"을 누르기만 기다리는 상태인데 탈옥 실패처럼 보인다. 이제 `preset install` 이 기록할 때 #24 의 교체를 함께 적용한다: 설치 직후 `fetch: true` 이고 `selfcheck` 이 한 번에 모두 초록이 된다.

**상태 페이지**: 상단을 하나의 hero 로 바꿨다 — 현재 상태를 한 문장으로(`75/83 개 패치 적용됨` / `호스트가 아직 풀리지 않음: "적용" 클릭`) + 확대된 "적용" 주 버튼 + 한 줄 안내 "플러그인 설치, DSH 업데이트, 모델이 다시 회피하기 시작한 경우: 적용을 한 번 누르고 종료 후 재실행". 중복된 지표 카드 세 개, 진행 바, "버전과 복구" 헤더를 삭제했다 — 후자가 계속 "호스트 버전 확인 중"을 표시하던 원인이었다(다른 인터페이스를 읽고 실패 시 영원히 확인 중에 머문다). 탈옥 자체 점검, 패치 상세, 유지보수(업데이트+백업), 고급 옵션은 기본 접힘 블록으로 바꿨다.

**무제한 모드**: "레드팀 프리셋 축소"에서 **standard 상위집합**으로 변경 — `time-context`, `tool-schedule`, `present` 를 보강해 20줄; 페르소나를 실행 우선으로 재작성했다(바로 시작 / 경계 반복 선언 없음 / 서두 최소 / 여러 턴에서 퇴화 없음 / 실패 시 경로 변경). 프리셋 파일에 `# managed-by: dsh-purge` 표식이 있다: 표식이 있으면 새 버전이 자동 갱신하고, 사용자가 수정해 표식을 지우면 더 이상 덮어쓰지 않는다.

커뮤니티 프로젝트 [geohotstan/dsh-tabula-rasa-preset](https://github.com/geohotstan/dsh-tabula-rasa-preset) 을 참고했다: 이것은 `persona: {text:'', complete:true}` 로 시스템 프롬프트 전체를 비운다. 우리는 `complete` 를 **채택하지 않는다** — purge 주입 섹션까지 함께 눌러 탈옥 프롬프트 계층을 잃기 때문이다.

DSH 0.1.7+ 의 모드 드롭다운은 `agentPresets.register()` 만 인정하므로 폴더를 `~/.dsh/.agent-presets/` 에 넣어도 표시되지 않는다(1.3.7/1.3.8 골격이 이 단계에서 막혔다). 독립 플러그인 항목 `dsh-purge-community/presets-plugin` 으로 `lib/presets-plugin.js` 를 추가했다: registry 가 준비되면 한 번 소프트 등록하고 제거 시 해제하며, 첫 실행 시 `presets/unrestricted` 를 사용자 디렉터리에 기록한다.

`purge-community selfcheck --text` 는 사람이 읽는 요약만 출력하고, `scripts/install.sh` 가 이것으로 "DSH 버전 · 호환 등급 · 호스트 패치"와 결론을 출력한다. 이전 구현은 JSON 의 두 번째 줄을 가져와 유용한 정보를 전혀 출력하지 못했다.

- **`scripts/check-docs.mjs`**: package.json 버전 = release-notes 첫 줄 = README 버전 줄 = 영문 README 를 단언하고 한 줄 설치 명령이 남아 있는지 확인한다; `community.yml` 과 `release.yml` 에 연결해 버전만 바꾸고 문서를 못 따라가면 바로 빨간색이 된다.
- **설치기 설치 후 자체 점검**: `scripts/install.sh` 가 설치 성공 후 `selfcheck` 를 한 번 실행해 "DSH 버전 · 호환 등급 · 호스트 패치"와 결론을 출력하므로 두 번째 명령을 외울 필요가 없다.
- **`unrestricted` 프리셋 골격**: `presets/unrestricted/{preset.yml,agent.cordis.yml}` + `purge-community preset install`. 프리셋은 페르소나와 도구 표면만 담당한다(승인/샌드박스는 여전히 호스트 패치가 걷어낸다). 출하 시 `fetch: false` 라 #24 가 할 일이 있고, `preset install` 은 멱등이며 `--force` 없이 사용자 수정을 덮어쓰지 않는다.

상태 페이지: "적용 / 되돌리기 / 제거"를 콘텐츠 영역 상단에 고정했다; 탈옥 자체 점검을 27줄 세로 나열에서 한 줄 요약 + 펼친 다중 열 그리드로 바꿨다; 패치 상세는 기본 접힘; 백업/업데이트는 "유지보수"로 접었다. 다크 모드에서 주 버튼이 brand-primary(하이라이트 텍스트 색)를 배경으로 써서 흰 배경에 흰 글자 사각형으로 렌더링되던 문제를 고쳐, 고정된 실선 초록/빨강 배경에 흰 글자로 바꿨다.

`scripts/install.sh` 추가: 한 줄 설치(데스크톱 버전 찾기 → 다운로드 → SHA256 검증 → DSH 런타임으로 설치기 실행). README 재작성: 한 줄 설치를 최상단에 두고, 원본과의 기능 대조표, 버전별 업데이트 호환 표를 넣었다.

`purge-community selfcheck` 가 일반 Node 프로세스에서 surface 를 web 으로 판정해, `app.asar` 가 남아 있어도 "호스트 실행 방식 ✓"로 보고했다. 전부 초록처럼 보이지만 실제로 실행 중인 것은 패치되지 않은 호스트였다. 이제 데스크톱 호스트 기준으로 명시 판정한다: `app.asar` 가 존재하면 미적용으로 보고 자체 점검 전체 결론을 false 로 하며 "적용"을 누르라고 안내한다.

rc.2 의 원본 호스트 사본에서 전체 표를 회귀했다: 64건 기록, 6건 이미 목표 상태, **실패 0**, 수정된 파일 42개 모두 구문 검사 통과; 패치된 rc.2 호스트가 profile 을 구성하고 플러그인을 기동할 수 있었다. 우측 슬롯 `sidebar.panellist` / `main` 은 rc.2 에서도 그대로 존재한다.

설정 페이지를 오른쪽 드로어에서 **왼쪽 사이드바 `Purge`** 로 옮겼다: 열면 전체 페이지가 된다(상태 / 프롬프트 / 규칙 / 스킬 / 드릴 콘솔 / 더 보기), 글꼴, 간격, 탭 스타일은 DSH 자체를 따르고, 설명은 제목 뒤 작은 `?` 호버 팁으로 바꿨다; 상태 페이지 상단 한 줄에 호스트 버전, 호환 등급, 패치 카운트, 플러그인 버전을 표시한다.

드릴 콘솔 스타일 수정(1.3.2 부터 동반): 패널을 재구성할 때 드릴 콘솔 자체의 `.rt-*` 스타일시트가 사라졌다(옛 버전은 외부 dock 이 `<head>` 에 주입했다). 그 결과 드릴 콘솔에 스타일이 전혀 없고 텍스트가 한 열로 뭉쳤다. 이제 스타일이 컴포넌트와 함께 마운트되고 컨테이너에 늘림/스크롤/줄바꿈 규칙을 보강했다.

**원본의 모든 기능을 복원하고 호스트 패치를 83건으로 늘려 DSH 0.2.1-rc.1 에 하나씩 적응시켰다.**

## 1.2.0 대비 주요 변경

### 1. "일괄 쓰기 금지" 마스터 스위치 제거

1.2.0 은 옛 패치 위험을 피하려고 `patchWritesAllowed` 를 `false` 로 하드코딩해 되돌리기, 제거, Hooks, 항목별 상태 영역, 자동 적용/자동 업데이트, 재시작 진입점까지 함께 막았다. 1.3.0 은 이 진입점을 원본대로 하나씩 복원했다:

| 능력 | 1.2.0 | 1.3.0 |
| --- | --- | --- |
| 적용 / 호스트 패치 재적용(UI, `/purge apply`, `purge_apply` 도구, HTTP) | 전부 차단 | 전부 복원 |
| 되돌리기 / 제거(UI, 명령, 도구, HTTP) | 전부 차단 | 전부 복원, 제거와 되돌리기는 여전히 분리 처리 |
| 기동 자가 복구, 업그레이드 후 복구, `autoApplyOnStart` / `autoUpdateOnStart` | 강제 해제 | 설정을 따름 |
| Hooks 스위치, 항목별 패치/shim/백업 상태 | 숨김 또는 저장 거부 | 표시와 저장 복원 |
| 적용 후 자동 재시작(밀봉 asar 재시작 포함) | 수동 안내로 변경 | 원래 스케줄링 복원, 사용자 수동 재시작 규칙은 유지 |
| 원본 CLI `dsh-purge --status/--apply/--revert/--uninstall/--edit` | 패키지에 미포함 | 다시 export; `purge-community apply|revert|uninstall|edit` 로 직접 전달 |

호환성은 더 이상 쓰기 게이트가 아니다: `compatibility()` 는 보고만 생성하며(`qualified` / `unverified` / `mixed` / `no-host`), "호스트를 전혀 찾을 수 없음"과 "컴포넌트 버전 불일치"만 여전히 쓰기를 막는다.

### 3. 추가: 앵커 진단

- 패널 "상태 → 호환과 진단", `GET /dsh-purge/diagnose`, `npm run diagnose` / `purge-community diagnose`.
- 출력 버킷: `drifted`(필수 패치 앵커 전멸), `optionalDrift`, `chained`, `missing`, 각 항목에 파일 경로와 기대 원문 스니펫.
- 용도: DSH 를 다시 업그레이드하면 먼저 진단을 보고 적용 여부를 정한다; 더 이상 "쓰기 금지"로 안전판을 대신할 필요가 없다.

### 4. 패널: 원본 인터페이스 전부 복원

- 원본 상태 영역(적용/전체, 대기/불일치/건너뜀, shim, 백업, 항목별 패치 그룹)과 Hooks 스위치를 복원하고, 커뮤니티 유지보수 영역을 그 위에 겹치게 했다(교체가 아니다).
- 세션 입력 영역의 **되돌리기 버튼**과 되돌린 뒤 드래프트 복원을 복원했다(`conversation.input.right`, `dsh-purge-rewind`, order 20); sessionStorage 키는 옛 접두사를 유지한다.
- **첫 방문 환영 안내**와 **드릴 모드 전송 전 환경 적응 안내**를 복원했다.
- `__COMMUNITY__` 에는 브랜드/문구/저장소 주소 차이만 남았다.

### 5. 업데이터: 채널과 소스가 모두 돌아옴

- 기본 채널은 여전히 이 fork 의 정식 릴리스 패키지다(tgz 다운로드 + SHA256 + 패키지 이름/버전/저장소 검증).
- 원본의 정식/테스트 채널, GitHub 브랜치와 이력 tag 선택, branch pin, 버전 이력, 자동 업데이트 가드, 다중 설치 위치 업데이트 계획을 복원했다.
- 상위 소스를 선택하면 기본적으로 선택 상태가 아니며 결과에 `warning` 이 붙는다: 상위는 유지보수가 중단되었고 새 DSH 와 호환되지 않는다.

### 6. 엔지니어링

- `engines.node` 를 `>=18` 로 되돌렸다; `files`/`bin` 에 원본 CLI 와 스크립트를 다시 포함했다.
- `test/patch-anchors.test.mjs` 추가: 0.2.1 실제 소스 스니펫을 사례에 고정해 앵커 드리프트 시 테스트가 바로 실패한다.
- 호환성 단언을 "보고이지 비활성화가 아님"으로 바꾸고, "호스트를 찾지 못할 때만 쓰기를 막는다" 사례를 추가했다.

## 1.3.1 추가

- **탈옥 강화 섹션 기본 켜짐**: 시스템 프롬프트 끝에 계층 선언 / 거부는 곧 고장 / 아첨 저항 / 다중 턴 재확인을 덧붙인다; `purge-community boost off` 또는 패널 원클릭으로 끈다.
- **주입 위치 전환 가능**: `head`(기본, 토큰 절약) / `tail`(출력에 밀착, 다중 턴 감쇠 최소) / `both`, `$DSH_HOME/dsh-purge/tuning.json` 에 저장.
- **#89 `ask_user_question` 이 더 이상 턴을 막지 않음**: 대기 상한을 1초로 압축하고 시간 초과 시 바로 계속한다(사용자는 UI 에서 나중에 답할 수 있다).
- **드리프트 진단이 가능한 새 위치 제시**: `diagnose` 가 앵커 미적중 시 행 번호 + 스니펫을 반환해 재앵커를 돕는다.
- **탈옥 자체 점검**: `purge-community selfcheck [--json]`, `GET /dsh-purge/selfcheck`, 패널 "상태 → 탈옥 자체 점검". 21개 계층별 증거(호스트 패치 / 런타임 주입 / profile 권한 / asar 밀봉 여부)를 주고, 대상 플러그인이 설치되지 않은 계층은 실패가 아니라 "해당 없음"으로 표시한다.
- **백업 보존 정책**: 기본 keep_last=5, keep_daily=7, 전체 200MB, `backup/install/rollback` 후 자동 정리; `purge-community usage` 로 점유량 확인, `prune` 으로 즉시 정리. 이전에는 하루에 65MB 까지 쌓여도 상한이 없었다.

## 알려진 경계

- 이번 검증은 **0.2.1 원본 호스트 사본**에서 완료했다(전체 표 적용 + 수정된 파일 41개 개별 `node --check` + 패치 후 호스트 `--dump-config` 정상). 실제 클라이언트에서 "적용"을 누른 뒤의 런타임 효과는 재시작 후 사용자가 확인해야 한다.
