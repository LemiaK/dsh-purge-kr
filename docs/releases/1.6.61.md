# 1.6.61

**알려진 제한:** GitHub 의 macOS, Windows, Linux 설치 및 런타임 검사는 모두 통과했다; 그러나 Windows 4090 의 전체 설치 검수는 Defender 가 옛 버전에 이미 있던 `skills/redteam/unauth-exploit.md` 를 격리해 중단되었으므로 그 장비에서 검수를 통과했다고 볼 수 없다. 옛 버전과 이 버전의 해당 파일 SHA256 은 동일하다. 이번에 보호 기능을 끄거나 제외를 설정하거나 스킬을 삭제하지 않았다; 이 문제는 계속 열어 둔다.

이번에는 유지보수 잠금, Web 하위 경로 요청, 업데이트 채널을 집중 수정하고 내장 프리셋의 원시 스킬 디렉터리 탐지를 복원했다.

- **#92**: 완전한 잠금 메타데이터를 원자적으로 게시한다; 해제 실패 시 상호 배제 게이트를 유지하고 원 작업을 재시도할 수 있게 한다; 소유권 변경과 읽기 실패를 구분한다. 설치 커밋 후 정리 오류는 현장을 보존하고 명확히 경고하며 더 이상 잘못된 롤백을 유발하지 않는다.
- **#106**: 패널 요청이 실제 배포 하위 경로를 따르게 해 상태, 설정 및 기타 인터페이스가 사이트 루트로 잘못 요청되는 것을 막는다.
- **PR #99**: 업데이트 전용 SOCKS5/HTTP(S) 프록시와 GitHub token 설정을 추가한다; 기존 환경 프록시를 유지하고 동시 인스턴스 자격 증명을 격리하며 공개 상태에서 인증 정보를 숨기고 TLS, 출처, SHA256 검증을 계속한다.
- **PR #103**: 사용자, 프로젝트, bundled 스킬 디렉터리 탐지를 복원한다; 사용자가 수정한 프리셋을 덮어쓰지 않고 스킬 자체의 호출 제한을 무시하지 않는다.
- 설치 전에 CLI 를 미리 찾는다; 프롬프트, 설정, 기존 기능을 유지하고 호스트 패치를 자동 적용하거나 재시작하지 않는다.

업데이트 채널에 기여한 Minggle, 스킬 탐지에 기여한 Steooenwolf-666 / hans, 잠금 문제를 분석한 Minervaowl7 에 감사한다.

**미포함**: #95 현장 리소스 손상 원인, #89 패키지 교체 도우미 문제, PR #102 서드파티 데스크톱 패키지 교체, PR #113 Cookie/header 수정. 이들은 계속 열린 상태로 두며 검증되지 않은 호스트를 호환으로 표시하지 않는다.
