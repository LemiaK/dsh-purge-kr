# 1.6.46

#67 수정: Windows/Electron 에서 의존성 스냅샷을 정리할 때 Junction 이 가리키는 외부 파일을 잘못 삭제할 수 있다.

- 스냅샷과 기타 재귀 정리 진입점을 링크를 따라가지 않는 삭제 방식으로 통일한다; 심볼릭 링크/Junction 은 링크 자체만 삭제하고 대상으로 재귀 진입하지 않는다. 기존 권한과 실패 복구 로직은 유지한다.
- 백업 정리, 업데이트 임시/롤백 디렉터리, 언팩 잔여물, 제거, 리소스 임시 디렉터리를 점검한다; 독립 설치기와 제거 도우미는 자체 포함 구현을 유지하고 테스트로 구현 드리프트를 막는다.
- 설치/롤백이 검증되었는데 정리만 실패하면 명확한 경고를 반환하고 잔여물을 보존한다; checkpoint 정리 오류를 더 이상 조용히 삼키지 않고 일부가 정리된 스냅샷으로 자동 롤백하지 않는다.
- 링크 보호 테스트와 실제 Windows Electron + pnpm 의 file/link 의존성 설치, 업그레이드, 롤백, 재업그레이드, 설치 실패 복구, 롤백 실패 복구 테스트를 추가했다; 링크 대상 파일 해시와 설정 바이트를 단계마다 대조한다.

**옛 Windows 사용자: 새 버전 독립 설치기로 먼저 업그레이드한다.** 옛 DSH 프로세스의 업데이트/롤백 코드는 새 패키지를 받아도 즉시 교체되지 않으므로 옛 정리 로직을 계속 실행할 수 있다. 먼저 제거하거나 캐시를 비우거나 잠금 파일을 삭제하지 않는다; 이미 잃은 외부 파일은 신뢰할 수 있는 출처나 백업에서 복구해야 하며 이 수정이 자동으로 재생성하지 않는다.

프롬프트, 기존 기능, 사용자 설정, 프록시를 수정하지 않고 패치를 자동 적용하거나 DSH 를 재시작하지 않는다. 명확한 격리 재현과 위치 파악을 제공한 @leaf0329 에 감사한다.

자세한 내용은 [영향 범위, 업그레이드 방법, 검수 기록](../maintenance-issue-67.md) 를 본다.
