# Purge Community 1.6.11 검수 기록

## 수정 범위

- #12: 제출자가 이후 정정한 `/rewind` 이름 충돌 재현에 따라 수정하고, 원 보유자는 유지하며 Purge 대체 명령을 등록한다. 되돌리기 기능을 끄거나 프로세스 수준 주기적 폴링으로 패널을 복구하는 방식이 아니다.
- #15: 올바른 permission 노드를 읽는다; 실행 중인 실제 기본 권한이 디스크 리터럴보다 우선한다. `inferred` / `unknown` 과 `broken` 을 구분한다. CLI JSON/text 종료 코드가 일치한다; 종료 코드 0 이 모든 것이 검증되었음을 뜻하지 않는다.
- 읽기 전용 상태 인터페이스는 connection/session 준비 상태에 의존하지 않는다; 서비스 지연 도착, 교체, 상위 플러그인 재로드, 제거는 모두 Cordis 가 회수하며 전역 타이머를 남기지 않는다.
- YAML 은 데이터로만 파싱하고 `!!js` 를 절대 실행하지 않는다. 사용자 권한을 자동으로 바꾸지 않는다. 호스트 패치 정의와 기존 기능은 유지한다.

## 검증

- Node 자동 회귀, 패널 컴포넌트 회귀, 릴리스 패키지 압축 해제와 진입점 import.
- Cordis 4.0.5 실제 생애주기: 서비스 지연 도착, 교체, 상위 플러그인 재로드, 제거 후 되살아나지 않음.
- Mac 실제 DSH Electron 44.7.0 + 공식 CommandRuntime: rewind 를 미리 점유해 원 명령과 대체 명령이 공존하는지 확인했고, 도구 3개, 프롬프트 섹션, 인터페이스 6종이 계속 등록되며 제거가 깨끗했다.
- Electron ASAR 자체 점검의 양방향 검증이 계속 통과하며 전역 noAsar 를 수정하지 않는다.

- Windows 11 4090 실기, 공식 Desktop 0.2.1-rc.2 / Electron 44.7.0: 격리 사본에 설치했고 프롬프트와 profile 설정 SHA256 은 변하지 않았다.
- 같은 Windows 실제 Electron + 공식 CommandRuntime 의 이름 충돌 통합 테스트 통과; 도구 3개, 프롬프트, 인터페이스 6종이 모두 등록되고 제거가 깨끗했다.
- Windows 대화형 DSH 를 완전히 재로드한 뒤 실제 HTTP status 가 1.6.11 을 반환했다; selfcheck 가 live permissionPresets 에서 danger-full-access / never 를 확인해 inferred, pinned=false 로 표시했고 원 설정을 수정할 필요가 없었다.

- Node 회귀 116건: Mac 은 111건 통과, Windows 전용 5건 건너뜀; 4090 Windows 전체 실행은 114건 통과, 플랫폼 조건으로 2건 건너뜀, 실패 0. 패널 컴포넌트 10건 및 UI 계약, 패키징 검사 통과.
- Windows 격리 사본에서 실제 백업 검증, 1.6.10 으로 롤백, 1.6.11 로 재업그레이드 통과, YAML 의존성이 설치 패키지에서 해석됨; 설정과 프롬프트는 변하지 않았고 자동 재시작은 없었다.
- 전체 실측에서 옛 테스트가 POSIX stat.mode 0600 을 Windows 에 적용한 오류를 수정했다; Windows 는 그 필드로 사설 ACL 을 증명하지 않는다. 세 플랫폼 CI 를 설치기 하위 집합이 아니라 전체 npm test 실행으로 바꿨다.
- 릴리스 절차는 세 플랫폼 전체 회귀, PowerShell 5.1/7 및 Windows 실제 Electron 인계 테스트 통과를 강제로 기다린 뒤 릴리스 패키지와 SHA256 목록을 생성한다.

검수는 모델이 프롬프트를 받았다거나 모든 Windows UI 버튼을 하나씩 눌렀다는 뜻이 아니다.
