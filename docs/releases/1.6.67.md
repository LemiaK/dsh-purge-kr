# 1.6.67

## 수정 내용

- Windows 업데이트 프록시 탐지가 읽기 전용 `reg.exe` 를 우선 쓰고 필요할 때 UTF-8 PowerShell 로 폴백해, 매번 PowerShell 콜드 스타트에 의존하지 않는다. 탐지 실패 시 HTTP 가 아직 전송되지 않았음을 표시하고 더 이상 GitHub API 불가로 뭉뚱그리지 않으며 조용히 직접 연결로 바꾸지도 않는다.
- 일시적 연결 리셋 같은 네트워크 오류는 최대 두 번 재시도하며 기존 요청 시간 초과와 리다이렉트 예산을 함께 쓴다. HTTP, 인증, 인증서, 파일 크기, 출처, SHA256 오류는 계속 명확히 보고한다.
- Windows 업데이트 자격 증명 파일이 일반 Users 읽기 권한을 상속하던 문제를 수정한다: 보호된 임시 디렉터리와 파일을 먼저 만들고 자격 증명을 쓴 뒤 원자적으로 교체한다; 옛 파일은 처음 읽을 때 권한을 조이고 내용은 그대로 둔다. 덮어쓰기가 실패하면 옛 파일을 보존한다.
- PowerShell 7 에서 기동된 프로세스와 호환한다: Windows PowerShell 5.1 도우미는 자체 시스템 모듈만 로드해 모듈 경로를 잘못 상속해 Get-Acl 로드가 실패하는 것을 막는다; 상위 프로세스나 시스템 환경은 수정하지 않는다.
- 키는 PowerShell 명령 인자, 환경변수, 로그에 들어가지 않는다; 손상된 JSON 진단도 더 이상 자격 증명 원문을 출력하지 않는다. 빈 키가 덮어쓰지 않고 명시적 제거로만 삭제되며 동작 선호가 따로 저장되는 의미를 유지한다.

## 실측과 경계

- Mac 과 Windows 11 4090 의 실제 공개 GitHub 릴리스 정보 요청이 모두 HTTP 200 을 반환했다; Windows 읽기 전용 레지스트리 탐지 3회는 약 9–11 ms 였고 PowerShell 대체 읽기 결과도 일치했다.
- 두 플랫폼 격리 Electron 44.7.0 에서 실제 HTTPS / CONNECT / SOCKS, 연결 리셋과 중간 단절, 전체 시간 초과, token 교차 호스트 격리, SHA256 검증을 확인했다. Windows 전용 38건 모두 통과; Mac 은 해당 33건 통과, Windows 전용 5건 명확히 건너뜀.
- Windows 에서 느슨한 상위 디렉터리의 ACL, 신규 생성/덮어쓰기/옛 파일 마이그레이션, 읽기 전용 대상, 실제 파일 점유와 해제 후 복구를 검증했다. 자격 증명은 모두 임시 테스트 가짜 값이다.
- CI 와 릴리스 절차에 같은 Electron 업데이트 채널 테스트를 넣었고 릴리스 패키지는 계속 세 플랫폼 설치기와 회귀 검사를 거친다.

이 버전은 공통 업데이트 채널과 자격 증명 보호만 수정하며 호스트 패치, 프롬프트, 자동 업데이트 선호를 바꾸지 않는다; 이번 테스트는 유지보수자의 정식 DSH 설정, 프록시, 보호 기능을 바꾸지 않고 자동 재시작하지도 않는다. ACL 은 암호화가 아니므로 관리자나 같은 사용자 프로세스의 읽기를 막지 못한다.
