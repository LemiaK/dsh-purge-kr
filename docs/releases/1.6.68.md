# 1.6.68

## 수정 내용

- "적용" 클릭 후 기본 비활성인 #18/#19 가 "처리 실패"로 잘못 집계되던 문제를 수정한다. `disabled` 는 이제 상태 페이지, 자체 점검과 같은 기준을 쓴다: 선택에 따라 꺼진 상태이며 실패가 아니다.
- 쓰기 오류, 권한 오류, 필수 앵커 불일치, 적중 수 이상, 부분 적용, 읽기 불가, 미지 상태는 계속 보고한다; 혼합 결과에서는 실제로 실패한 항목만 나열하고 비활성 항목이 이상을 가리지 않게 한다.
- 기능 패치, 기본 스위치, 프롬프트, 설정, 프리셋을 바꾸지 않았다. #18/#19 를 자동으로 켜지 않고 DSH 를 자동 재시작하지도 않는다.

## 검증

- PR #124 최종 커밋의 GitHub 검사 8건이 모두 통과했으며 세 플랫폼 설치와 npm 런타임 검증을 포함한다.
- Mac 전체 439건: 421 통과, 18건은 플랫폼/조건에 따라 건너뜀; Windows 11 4090: 413 통과, 26건은 플랫폼/조건 건너뜀. 건너뛴 항목을 통과로 세지 않았다.
- 양쪽 모두 실제 격리 Electron 44.7.0 에서 apply, 대상 누락, 부분 상태 전용 테스트가 각각 15/15 였다; 패널 26건, UI 계약, 문서, 생성 bundle 일관성이 통과했다.
- 수정을 제거한 음성 대조에서는 테스트 실패가 다시 발생한다; 기본 비활성일 때 대상에 쓰지 않고 백업도 만들지 않는지, 실제 오류가 섞였을 때 올바른 실패 ID 가 유지되는지도 함께 확인한다.

[ShiTan-677](https://github.com/ShiTan-677) 님이 [PR #124](https://github.com/kingcharleslzy-ai/dsh-purge/pull/124) 를 제출했다.

이 버전에는 아직 검증되지 않은 NEXT 대응 PR #102 나 백업 옵션 PR #115 가 포함되지 않는다. 릴리스 패키지는 세 플랫폼 검사 통과 후 빌드되며 SHA256SUMS.txt 가 첨부된다; 사용자의 기존 설치가 이번 릴리스 때문에 메인테이너에 의해 자동 재시작되지는 않는다.
