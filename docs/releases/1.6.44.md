# 1.6.44

옛 버전 마이그레이션과 마켓 설치 안내를 고친다; 호스트 패치나 프롬프트 동작은 바꾸지 않는다.

- 옛 `dsh-purge` 의 알려진 진입점 참조를 커뮤니티 패키지로 마이그레이션한다; 설정 값, 프롬프트, 미지 옵션, 권한, 다른 플러그인은 보존한다. 옛 패키지는 롤백용으로 남기고 Purge bundle 은 하나만 활성화한다.
- 설치 후 새 프로세스로 패키지 진입점과 의존성을 확인한다. 설치나 검증이 실패하면 설치 전 의존성 트리, 매니페스트, 잠금 파일을 복원한다; 동시 수정이 있으면 덮어쓰기를 중단하고 복구 디렉터리를 보고한다.
- 옛 버전으로 롤백할 때 패키지 참조를 역방향 마이그레이션하고 이후 사용자가 수정한 설정 값을 보존한다. 식별할 수 없는 사용자 정의 / 수동 insert 진입점은 명확히 오류를 내고 복구하며 자동으로 삭제하거나 비활성화하지 않는다.
- 아카이브는 SHA256 별 디렉터리에 저장해 고정 파일 이름이 옛 설치 소스를 덮어쓰지 않게 한다. 설치 메타데이터는 정식 패키지의 안정 다운로드 별칭을 쓴다.
- 마켓 마이그레이션 안내를 추가해 서드파티 웹 수록, DSH format-1 인덱스, 공식 설치 CLI 를 구분한다; 무효한 bare npm 패키지 이름을 쓰지 않고 사용자에게 제거 후 재설치를 요구하지 않는다.

테스트: Mac 과 Windows 11 실기 모두 원본 1.1.71 → 커뮤니티 1.6.44 → 롤백 → 롤백 전 백업 복원 → 재업그레이드, 그리고 검증 실패 복구를 완료했다. 설정, 프롬프트, 규칙 센티널은 변하지 않았고 macOS 는 설정 파일 권한도 변하지 않았음을 함께 확인했다. 전체 Node 테스트 323건(311 통과, 12건 플랫폼 관련 건너뜀, 실패 0), 패널 테스트 13건 통과. 격리 DSH_HOME 을 쓰고 사용자 DSH 를 기동/재시작하지 않으며 프록시를 바꾸지 않는다.

서드파티 마켓 수정은 상대가 병합·배포해야 한다; 우리 릴리스 패키지가 이미 설치된 서드파티 마켓을 자동으로 다시 쓰지 않는다. 자세한 내용은 [마이그레이션 안내](https://github.com/kingcharleslzy-ai/dsh-purge/blob/master/docs/MARKET-MIGRATION.md) 를 본다.
