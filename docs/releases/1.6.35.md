# Purge Community 1.6.35

## #40: macOS 수동 종료 후 패키지 교체와 진단 일관성

- macOS "적용"이 재시작만 안내하고 아카이브 패키지 교체를 예약하지 않던 문제를 수정한다. 이제 독립 도우미를 먼저 띄우고 대상 앱과 하위 프로세스가 완전히 종료되기를 기다린 뒤 원본 `app.asar` 를 검증하고 보존한다. DSH 를 종료하거나 죽이거나 다시 열지 않는다.
- 대기 중 아카이브 변화, 언팩 주 진입점 또는 runtime 불완전, 쓰기 불가, 도우미 기동 실패, 시간 초과는 모두 실패 상태를 명확히 유지한다. "예약됨"을 "완료"로 취급하지 않는다.
- `host-status.handoff` 와 패널 `asar_handoff` 는 선택된 설치의 기록을 공유하며, 미예약, 종료 대기, 완료, 실패, 시간 초과, 기록 읽기 불가, 옛 기록과 새 아카이브 충돌을 구분한다. 디스크가 여전히 밀봉 상태인 경우, 실제 누락, 런타임 미지는 계속 표시한다.
- 독립 터미널에서 Desktop 대상을 지정해도 CLI/Web 프로세스 기준으로 `desktop-shell` 을 찾아 거짓 누락을 내던 문제를 수정한다; 다른 설치의 파일을 가져와 결과를 채우지 않는다.
- #71 은 현재 데이터 디렉터리 안에 서드파티 프리셋 계열이 전혀 없을 때만 "해당 없음"으로 표시한다. 이미 선언되었거나 존재하는 설치에서 파일이 빠지면 계속 누락으로 보고한다; 손상된 YAML 과 확정할 수 없는 설정은 성공으로 세지 않는다.

## 검증과 경계

macOS 실제 프로세스 종료 테스트와 실제 Electron 44.7.0 생애주기를 추가했다: 원본 아카이브 기동 → 테스트 앱 자체 종료 대기 → 백업 검증 → 자동 재오픈 없음 → 명시적 2차 기동으로 언팩 디렉터리 읽기; 격리 설정은 바이트 단위로 변하지 않았다. 음성 사례는 업데이트 충돌, 진입점/runtime 누락, 시간 초과, 기동 실패, 옛 잠금, 손상된 기록, 백업 유실을 커버한다.

세 플랫폼 설치/제거/실패 롤백, Windows 실제 Electron 패키지 교체, macOS/Windows 실제 Cordis 진단, Linux 공식 npm 호스트 검수를 그대로 유지한다. 패치 표, Windows 패키지 교체 구현, 권한, 프롬프트, 프리셋, 자동 업데이트 설정은 바꾸지 않았다.

이 테스트는 보고자의 macOS 15.7.4 / DSH nightly 설치 확인을 대신하지 않는다. CLI 는 런타임 권한 증거가 없으면 여전히 unknown 을 반환하며, 빨간색을 없애려고 권한을 바꾸지 않는다.

## 사용과 복구

플러그인 업그레이드 자체는 패치를 자동 적용하거나 재시작하지 않는다. 사용자가 데스크톱 Purge 에서 "적용"을 누른 뒤 패키지 교체 상태가 "완전 종료 대기"인지 확인하고 **⌘Q** 로 완전히 종료한다; 독립 진단이 `handoff.phase=complete` 를 확인한 뒤 DSH 를 직접 연다. 창만 닫는 것은 프로세스 종료가 아닐 수 있다. 도우미는 최대 30분 대기한다.

장애 시 먼저 상태와 백업을 보존하고 [#40 유지보수 안내](../maintenance-issue-40.md) 에 따라 점검한다; 알림을 없애려고 아카이브나 잠금을 삭제하거나 권한을 바꾸지 않는다. 플러그인 패키지 롤백과 호스트 아카이브 복구는 별개이며 옛 사용자 설정으로 현재 설정을 덮어쓸 수 없다.
