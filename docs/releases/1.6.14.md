# Purge Community 1.6.14 검수 기록

## 수정 범위

- #20: 원자적 교체가 만든 새 inode 가 rwx 권한을 상속하지 않아 shell 런처가 0755 에서 0644 로 바뀌었다. 범용 atomic-files 모듈을 분리해 동기/비동기 교체가 옛 권한을 유지하고, 복사와 롤백이 원본 파일 권한을 유지하게 했다. 고유 임시 이름으로 동시성 충돌을 피하고, 쓰기, chmod, rename 실패 시 임시 파일을 정리하고 오류를 던진다.
- 공식 CLI 의 백업 실패는 이제 교체를 중단하며, 설정 읽기/쓰기 오류는 report.ok=false 로 보고한다. 이미 있는 백업은 덮어쓰지 않고, 식별된 옛 런처가 모든 실행 비트를 잃은 경우 현재 읽기 비트에 대응하는 실행 비트만 보충하며 내용과 읽기/쓰기 권한은 유지한다.
- #19: host-status 와 상태 인터페이스 host_layout 을 추가해 대상의 디스크 레이아웃과 현재 서비스 기동 진입점을 읽기 전용으로 구분한다; 아카이브 존재만으로 "현재 프로세스가 아카이브를 로드했다"고 추론하던 옛 패널 문구를 바로잡았다. 진단은 전체 명령행이나 환경 변수를 반환하지 않는다.

## #19 결론의 경계

격리 디렉터리에서 재현된다: app.asar 와 언팩 디렉터리가 모두 있을 때 기존 sealedAsarHandoff 는 Web surface 에서 null 을 반환하고 Desktop surface 에서는 해당 아카이브를 반환한다. 이는 보고서의 Web 컨텍스트 단서와 일치하지만 보고자가 실제로 실행한 전체 호출 체인을 증명하지는 않는다. 테스트는 종료/패키지 교체 도우미를 기동하지 않았고 아카이브도 이동하지 않았다.

같은 디스크 레이아웃이 archive_entry, unpacked_entry 또는 unknown_runtime 에 대응할 수 있다; 아카이브가 이동된 뒤에도 원래 프로세스 진입점은 아카이브를 가리킬 수 있다. 패널과 에이전트는 이제 증거를 각각 봐야 하며 디스크 기록 횟수를 런타임 로드 증명으로 볼 수 없다.

**#19 는 열린 상태로 유지한다; 이 버전은 전체 패키지 교체 흐름을 고쳤다고 주장하지 않는다.** 기존 패키지 교체 도우미, 재시작 스케줄링, 호스트 패치, 프롬프트, 프리셋 정책, 업데이트 선호는 모두 바뀌지 않았다.

## 검증

- macOS Node: 128건, 123 통과, 5건 Windows 전용 건너뜀, 실패 0.
- 패널 컴포넌트: 11건 모두 통과; 패키징, 인터페이스, 형식 검사 통과. 신규 사례가 증거 없는 옛 인터페이스, 다른 인스턴스, 언팩 진입점을 커버하며 로드 성공/실패를 더 이상 잘못 주장하지 않는다.
- 실제 Electron 44.7.0: 신규 권한/레이아웃 테스트 7건 통과, 기존 ASAR 자체 점검 테스트 통과. 임시 디렉터리를 썼고 데스크톱 GUI 를 기동하거나 실행 중인 DSH 를 재시작하지 않았다.
- #20 실제 PC 재현: 공식 런처가 0644 였다. 파일과 권한 기록을 먼저 저장한 뒤 0755 로 복구했고 내용 SHA256 은 변하지 않았으며 공식 dsh --help 직접 실행이 정상이었다. 앱 디렉터리에 재귀 chmod 를 하지 않았다.
- 실패 주입이 쓰기, chmod, rename, 백업 실패를 커버한다; 원본 내용과 기존 백업이 보존되고 임시 파일이 회수된다; 0755/0750/0700 및 0600/0640 권한을 커버한다.
- 릴리스 절차는 macOS, Linux, Windows 설치기 CI 통과를 추가로 요구한다; Windows 전체 데스크톱 UI 는 이번에 다시 검수하지 않았고 옛 버전 실기 기록으로 이번 결과를 대신하지 않는다.

사용자 데이터, 스크린샷, 실제 호스트 주소, 프롬프트, 사설 백업은 릴리스 패키지에 포함되지 않는다.
