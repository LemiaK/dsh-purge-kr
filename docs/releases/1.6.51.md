# 1.6.51

## 데스크톱 위치 판정과 설치 호환성(PR #78)

- 이름을 바꿨거나 사용자 지정 경로에 설치된 경우 DSH 호스트 패키지와 CLI 구조로 식별하며, 일반 Electron 앱은 app.asar 가 있다는 이유만으로 DSH 로 오인하지 않는다; 손상된 우선 아카이브는 만료된 사본으로 폴백하지 않는다.
- 명시적으로 선택한 대상이 무효면 중단하고 몰래 다른 앱을 고르지 않는다; 마운트 볼륨 순회와 임의 상위 디렉터리 스캔을 제거하고 유효 대상이 여러 개면 명확한 선택을 요구한다.
- macOS 는 시스템 plutil 로 XML/바이너리 plist 를 읽고 누락되거나 무효한 필드, 경로 이탈, 제어 문자, 심볼릭 링크 탈출을 거부하며 실행 파일 이름을 더 이상 추측하지 않는다.
- 다중 아키텍처 런타임 링크가 현재 프로세스 아키텍처의 유효 디렉터리를 가리켜 공식 CLI 가 pnpm 을 로드하게 한다. 이미 있는 실제 디렉터리, 유효 링크, 복구 백업은 보존한다; 충돌, 권한 오류, 런타임 수정 실패는 계속 표시하고 CLI shim 누락을 더 이상 성공으로 보지 않는다.
- README 첫 화면에 원저자 샤오양 / YuJunZhiXue 와 복원된 원 저장소 링크를 보충했다; 기존 라이선스와 출처 표기는 유지한다. 호환성 기여를 제공한 @5hux1n 에 감사한다.

- 프로젝트 표시 이름을 **dsh-purge Community** 로 통일했다; 패키지 이름 `dsh-purge-community`, 내부 플러그인 ID, 설정 및 백업 경로는 변하지 않는다.

## 테스트와 범위

PR #78 의 GitHub 검사 8건이 모두 통과했다. 병합 전 전체 자동 테스트 328건 통과, 실패 0, 12건 플랫폼/조건 건너뜀; Mac ARM64 와 Windows 11 x64 의 격리 Electron 에서 각각 5조의 실제 공식 CLI/pnpm 설치, 옛 버전 마이그레이션, 업그레이드, 롤백, 재업그레이드, 실패 복구를 완료했다. 아키텍처 디렉터리의 pnpm 을 실제로 실행했고 대조한 정식 설정 파일은 변하지 않았다. 자세한 증거는 [검수 기록](../pr78-runtime-integrity.md) 을 본다.

이 버전의 변경은 일반 위치 판정, 설치, 런타임 로드에 한정된다; 기존 기능을 삭제하지 않고 사용자 프롬프트, 설정, 프리셋을 수정하지 않으며 DSH 를 자동 재시작하지 않는다. 실측은 모든 서드파티 DSH 변형, 크로스 아키텍처 에뮬레이션, 마켓 UI 를 모두 커버했다는 뜻이 아니다. 새 버전을 설치한 뒤 사용자가 편할 때 직접 완전히 종료하고 DSH 를 다시 연다.
