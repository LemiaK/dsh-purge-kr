# 1.6.10 Windows 언팩 후 재업데이트 검수

1.6.9 의 데스크톱 패키지 교체와 설정 인터페이스 테스트가 통과한 뒤, 공개 설치 진입점 재측정에서 다른 단계의 문제를 발견했다: 패키지 교체 후 다시 설치하면 CLI 가 app/runtime 아래의 pnpm 을 찾지 못한다. 1.6.9 는 즉시 프리릴리스로 전환해 정식 업데이트로 배포하지 않는다; 이미 배포된 tag 는 다시 쓰지 않는다.

## 근본 원인과 수정

Windows junction 의 상대 대상은 프로세스 작업 디렉터리 기준으로 해석되므로 기존 `..\runtime` 이 잘못된 위치를 가리킬 수 있었다. 같은 설치의 resources/runtime 절대 경로로 바꿨다; 옛 잘못된 링크는 이름을 바꿔 보존하고 링크 대상이나 디렉터리 내용을 삭제하지 않는다. 이미 있는 실제 디렉터리나 다른 유효 런타임 링크와 충돌하면 중단하고 임의로 덮어쓰지 않는다.

수정은 호스트 언팩과 독립 설치기에 함께 적용했다. 설치기는 현재 인스턴스의 언팩 CLI 를 호출하기 전에 링크를 확인한다; 패키지 교체 전에 pnpm 런타임을 쓸 수 없으면 도우미가 원본 아카이브를 보존하고 오류를 낸다. 옛 버전의 이미 고장난 업데이터는 새 로직을 자동으로 로드할 수 없으므로 README 의 독립 Windows 설치 진입점으로 1.6.10 을 설치한다.

## 검증 완료

- Windows 11, 실제 공식 DSH Desktop 0.2.1-rc.2, 독립 앱, profile, user-data-dir.
- 실제 아카이브가 이동되고 GUI 가 다시 로드된 상태에서 1.6.9 에서 1.6.10 후보를 설치했다; 옛 잘못된 링크가 보존되었고 원시 Desktop CLI 의 pnpm 호출이 성공했으며 프롬프트와 설정 SHA256 은 변하지 않았다.
- 위 언팩 호스트에서 실제 스냅샷, 1.6.8 로 롤백, 1.6.10 으로 재업그레이드를 완료했다; 현재 프롬프트와 백업 후 추가된 내용이 모두 유지되었다. 스냅샷 즉시 검증에 성공했고 이후 옛 스냅샷은 기존 보존 정책에 따라 정리했으며 테스트를 위해 사용자 보존 설정을 바꾸지 않았다.
- Windows 전용 16건 통과: 실제 Electron 부모 프로세스 종료 인계, 런타임 누락 시 패키지 교체 거부, 절대 junction, 잘못된 링크 보존, 설치기의 현재 인스턴스 위치 판정, 원시 설정 호환 포함.
- macOS 메인 테스트 103건 통과, Windows 조건부 5건 건너뜀; 패널과 Electron ASAR 회귀 유지.

1.6.9 의 #9, #10, PR #11 수정은 계속 유지되며 해당 검수 기록을 본다. UU 마우스 자동화가 불안정하므로 모든 Windows 컨트롤, 계정 로그인, 임의 모델 출력을 사람이 조작해 검증했다고 주장하지 않는다. 사용자 기본 DSH 데이터, 프록시, 이미지 생성 서비스를 바꾸지 않았다. 플러그인 기본값은 여전히 자동 재시작이 아니며 테스트 재시작은 사용자가 승인한 Windows 격리 사본에서만 수행했다.
