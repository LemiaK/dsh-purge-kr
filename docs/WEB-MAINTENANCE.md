# Web / Headless 유지보수 위치 판정(issue #3)

이 수정은 유지보수 인터페이스, CLI, 읽기 전용 자체 점검의 인스턴스 식별로 범위를 한정하며, 권한 선택, 패치 표, 프롬프트, 기존 정리 정책을 바꾸지 않는다.

## 백업 목록과 작업 결과

- 유지보수 패널에 들어가거나 다시 마운트할 때 목록을 읽는다. 수동으로 새로고침할 수 있다.
- 읽는 중, 읽기 실패, 백업 없음을 각각 표시하며 실패를 빈 목록으로 위장하지 않는다.
- 롤백 대상을 자동으로 선택하지 않는다. 선택한 백업이 더 이상 없으면 선택을 비운다.
- 업데이트, 롤백, 백업이 실패하면 목록만 다시 읽고 쓰기 작업을 자동으로 재시도하지 않는다. 실패 과정에서 이미 만들어진 복구 스냅샷도 볼 수 있다.
- HTTP 200 은 작업 성공과 같지 않다: JSON 의 `ok:false`, 오류 배열, 부분 성공까지 실제 결과를 표시한다.
- 업데이트가 성공하면 버전과 재시작 안내를 표시한다. 재시작이 필요한 것은 서버 측 DSH 프로세스이며, 브라우저만 새로고침해서는 백엔드가 다시 로드되지 않는다. 플러그인이 사용자를 대신해 서비스를 멈추거나 재시작하지 않는다.

## 현재 profile

유지보수, 백업, 권한 자체 점검은 같은 파서를 공유하며 다음 순서로 정보를 쓴다:

1. 호출자가 명시한 profile / `PURGE_PROFILE_DIR`.
2. 호스트 기동 인자에 있는 현재 `DSH_HOME/profiles/<name>` 디렉터리.
3. `--profile <name>` 또는 `--profile=<name>`.
4. `DSH_PROFILE`.
5. 유일하게 초기화된 profile(디렉터리에 package.json 이 있다).

profile 이 여러 개인데 명확한 단서가 없으면 바로 오류를 낸다. desktop 을 기본값으로 고르지 않는다. 명시한 디렉터리가 없거나 기동 인자와 DSH_HOME 이 충돌해도 조용히 다른 디렉터리로 바꿔 고르지 않는다.

예를 들어 서비스가 실제로 web profile 을 쓸 때는 **해당 서비스의 기동 환경**에서 `DSH_PROFILE=web` 을 설정한다. 사용자 지정 디렉터리는 `PURGE_PROFILE_DIR` 을 쓴다. 이 변수는 현재 대상만 알려 주며 샌드박스나 승인 권한을 설정하지 않는다.

## 설치 CLI

명시한 `PURGE_DSH_CLI` 가 여전히 우선하며, 현재 서비스가 쓰는 실행 런처나 npm CLI 의 `.js/.mjs/.cjs` 파일을 가리킬 수 있다.

지정하지 않으면 설치기는 현재 기동 경로나 대상 호스트 안에서만 찾는다: npm 배포는 `@deepseek-ai/dsh` 의 package.json 에 선언된 `bin.dsh` 를 읽고, Desktop 은 그 인스턴스 자체의 Resources 를 쓴다. PATH, 다른 전역 npm 설치, 다른 데스크톱 앱에서 CLI 를 추측하지 않는다.

하위 프로세스는 현재 서비스의 Node 로 JS CLI 를 실행하며 현재 `DSH_HOME` 과 선택한 profile 을 넘긴다. `purge-community` 를 독립 실행할 때 기동 정보로 대상을 확정할 수 없으면 `DSH_BASE` 나 `PURGE_DSH_CLI` 를 명확히 설정한다. 다른 설치를 추측하게 두지 않는다.

## Web 과 Desktop 공존

읽기 전용 자체 점검의 "호스트 실행 방식"은 현재 검사 중인 호스트 경로를 대상으로 한다:

- Web: 데스크톱 app.asar 검사는 "해당 없음"이고 앱 수와 총계가 모두 0 이라 레이아웃 실패로 세지 않는다.
- Desktop: 그 대상 자체의 app.asar 만 검사하며 다른 데스크톱 설치를 스캔하지 않는다.
- 대상이 불명확하거나 읽을 수 없음: 확정할 수 없다고 보고하며 성공으로 처리하지 않는다.

권한 항목은 여전히 실제 profile 만 읽는다. 사용자가 의도적으로 승인이 필요한 권한을 골랐다면 원래 설정과 실제 상태를 유지하며, 자체 점검을 전부 초록으로 만들려고 자동으로 조정하지 않는다.

## 검증 범위

회귀는 React 패널 마운트/재진입, 비즈니스 실패, 부분 업데이트, 실패 후 스냅샷, 현재/충돌 profile, npm CLI 하위 프로세스 인자, Web/Desktop 공존, 미지 상태를 포함한다.

CLI 실행 테스트는 임시 디렉터리에 둔 통제 가능한 npm CLI 테스트 진입점을 쓰며, 사용자 DSH 에 설치하지 않았고 실제 Linux Web 서비스나 모든 패치의 엔드투엔드 검수를 마쳤다고 주장하지 않는다.
